# Seedup UI 작업 계획

작성일 2026-11-18. 서비스 전체 계획은 [service-plan.md](../service-plan.md)에 있고, 이 문서는 그중 화면과 사용 경험만 다룹니다.
기준은 서비스 계획과 같습니다. **개발자와 바이브코더가 매일 쓰고, 돈을 내고서라도 쓸 서비스인가.**

## 원칙

- **디자인 기준:** [DESIGN.md](../../DESIGN.md)의 토큰(색, 글자 크기, 굵기 400/600/700, 간격, 모서리)과 문구 규칙(작은 머리말 금지, 가운뎃점 금지, 붙은 화살표 금지)을 모든 새 화면에 적용합니다.
- **검사:** 화면을 바꿀 때마다 Hallmark(`sloplint`)로 실제 사이트를 검사해 FAIL 0건을 유지합니다. 밝은 화면, 어두운 화면, 휴대폰 폭(375px)을 모두 캡처해서 봅니다.
- **로그인한 화면도 직접 봅니다.** 지금까지 작업대, PRD 생성, MCP 연결 화면은 로그인이 안 되어 확인하지 못했습니다. 테스트 계정으로 확인하는 방법을 먼저 만듭니다.
- **빈 화면을 보여 주지 않습니다.** 데이터가 없으면 숨기거나, 무엇을 하면 채워지는지 알려 줍니다.

## 1. 지금 바로 정리할 것

| 할 일 | 지금 상태 | 끝난 기준 |
|---|---|---|
| 남은 가운뎃점과 '기준 통과' 문구 | 실제 사이트의 기회 표(`GitHub · HN`, '0 기준 통과'), 오늘의 신호 머리줄(`· 기회 분석`)에 남아 있음 | 실제 사이트 전체에서 0건 |
| 빈 프로젝트 화면 | "아직 정리된 프로젝트가 없습니다"가 탐색 메뉴에 그대로 노출 | 데이터가 없으면 메뉴에서 숨김 |
| '인기' 탭 | 위쪽이 거의 논문이라 읽을 글처럼 보이지 않음 | 첫 10개 중 개발과 먼 주제 0개, 글과 논문이 섞여 보임 |
| AI 제품 목록 | 개발과 먼 제품(영업 관리, 통역기)이 섞임 | 개발 도구만, 또는 '개발 도구' 필터가 기본 |
| '오늘의 신호' 이름과 문구 | 7개 문제가 매일 거의 안 바뀌는데 '오늘'이라고 함 | 실제 변화 속도에 맞는 이름(주간)과 "이번 주 달라진 것" 중심 |
| 맞춤 추천 화면 확인 | 작업대 '나를 위한 추천', 읽을 글 '나에게 맞는' 탭을 새로 만들었지만 로그인해서 보지 못함 | 로그인한 상태로 캡처, Hallmark FAIL 0건 |
| MCP 연결 화면 확인 | 버튼 한 번 연결로 바꿨지만 로그인해서 보지 못함. Cursor, VS Code 설치 창이 실제로 열리는지도 모름 | 세 버튼 모두 실제로 연결까지 확인 |

## 2. 구조: 들어와서 무엇을 할지 바로 알게

| 할 일 | 이유 | 끝난 기준 |
|---|---|---|
| **메뉴를 세 덩어리로:** 발견(읽을 글, 오픈소스, AI 도구, 오늘의 신호), 만들기(PRD, 에이전트), 내 공간(작업대, 보관함, 내 저장소) | 지금은 읽을 글, 탐색(트렌드, 오픈소스, AI 제품, 프로젝트), 아이디어 평가, PRD가 흩어져 있어 어디서 시작할지 모름 | 메뉴 항목이 덩어리별로 묶임. 같은 내용이 두 메뉴에 있지 않음 |
| **첫 화면 메시지:** 지금은 "개발자가 쓴 글로 PRD를 만듭니다"라서 PRD 도구로 보임. 매일 보는 곳(큐레이션)을 앞에, PRD와 에이전트를 그 결과로 | 매일 다시 오게 만드는 것은 큐레이션 | 첫 화면 첫 줄이 서비스 정의(AI로 만드는 사람이 매일 보는 곳)와 맞음 |
| **읽은 것에서 만들 것으로:** 글, 저장소, AI 도구마다 활용 아이디어 한 줄과 "이걸로 PRD 시작" | 지금은 저장소에만 활용 아이디어가 있어 큐레이션과 PRD가 따로 놂 | 모든 콘텐츠 상세에 두 가지가 있음 |
| **첫 방문에서 쓸모 느끼기:** 가입 직후 관심 분야를 고르면 바로 맞춤 추천과 맞는 문제가 보이게 | 가입 뒤 몇 분 안에 "쓸 만하다"는 순간이 와야 남음 | 가입에서 첫 맞춤 추천까지 1분 이내, 그 비율을 측정 |
| **아이디어 평가와 PRD 정리:** 둘이 비슷한 일을 함 | 바이브코더가 어느 쪽을 써야 할지 모름 | 하나로 합치거나, 각자 하는 일이 화면에서 분명히 다름 |

## 3. 속도와 무게 (화면 쪽)

실측은 [service-plan.md 3-1](../service-plan.md#3-1-화면-속도)에 있습니다.

| 할 일 | 지금 | 끝난 기준 |
|---|---|---|
| 읽을 글 JavaScript 줄이기 | 19개 파일, 압축 전 약 491KB | 250KB 이하 |
| `/trends` HTML 줄이기 | 539KB | 100KB 이하(필요한 열만, 처음엔 일부만 보여 주기) |
| 헤더의 관리자 확인 | 모든 화면에서 `/api/auth/is-admin`을 따로 요청 | 서버에서 한 번에 판단, 추가 요청 0번 |
| 글꼴 | 한 화면에 Pretendard 조각 17개, 약 440KB | 쓰는 굵기(400/600/700)만, 첫 화면에 필요한 조각만 먼저 |
| 쓰지 않는 물리 효과 코드 | `chip-pile.ts`, `EvidenceCertificate.tsx`, `matter-js`가 남아 있음 | 화면에서 쓰지 않는 것을 확인하고 삭제 |
| 로딩 화면 | 모든 이동에 같은 빈 로딩 화면 | 목록과 상세는 모양을 미리 보여 주는 로딩 |

## 4. 아직 덜 된 화면

| 할 일 | 지금 상태 | 끝난 기준 |
|---|---|---|
| **PRD 기능 명세, 유저플로우, 와이어프레임 탭** | 정리만 했고 다시 설계하지 않음. 문서 탭에 비해 완성도가 낮음 | 세 탭이 문서 탭과 같은 수준. 각 항목에서 근거 원문으로 바로 이동 |
| **영어 화면** | 화면 26개 중 6개만 영어 지원(첫 화면, 오늘의 신호, 기회 상세, PRD 두 화면). 읽을 글, 보관함, 내 저장소, 로그인, 프로필, 검색, 트렌드 등 20개는 한국어 고정 | 언어와 시장을 정한 뒤(서비스 계획 7절) 범위 결정. 해외도 본다면 20개 모두 |
| **휴대폰 화면** | 주요 화면은 점검했지만 작업대, 보관함, 프로필, 내 저장소는 휴대폰 폭으로 확인하지 않음 | 모든 화면 375px에서 가로 넘침 0, 버튼 줄바꿈 0 |
| **빈 상태, 오류 상태, 로딩 상태** | 화면마다 문구와 모양이 다름 | 같은 컴포넌트와 같은 문구 규칙 |
| **계정과 데이터 삭제** | 화면이 있는지 확인 필요 | 프로필에서 계정, 킵, PRD, 연결 토큰을 지울 수 있음 |
| **도움말과 피드백** | MCP 연결 안내, 자주 묻는 질문, 버그 신고 경로가 없음 | 모든 화면에서 피드백을 보낼 수 있고, MCP 도움말 화면이 있음 |

## 5. 새 기능의 화면 (서비스 계획 6절과 함께)

새 기능을 만들 때 화면도 같은 기준으로 처음부터 설계합니다.

| 기능 | 화면에서 꼭 보여야 할 것 |
|---|---|
| 만들 가치 검증 리포트 | 한 장으로 끝나는 결론(만들 만한가), 근거 원문과 출처, 경쟁 도구, 혼자 만들 때 규모, 첫 사용자 후보. 공유 링크용 공개 화면 |
| 내 스택 레이더 | 내 저장소의 의존성별 소식, 왜 나에게 중요한지 한 줄, 할 일(교체, 업데이트, 지켜보기) |
| PRD와 코드 대조, 배포 전 점검 | 기능별 상태(완료, 빠짐, 기준과 다름), 위험도 순 목록, 항목마다 고치기 프롬프트 복사 버튼 |
| 측정(관리자) | 방문, 킵, PRD, 에이전트 연결, 재방문 비율. 수집 작업 성공 여부, PRD 성공률과 시간 |

## 6. 작업 순서

1. **1절 정리**와 로그인 화면 확인 방법 만들기
2. **3절 속도와 무게** (서비스 계획 1단계의 화면 속도 작업과 함께)
3. **2절 구조** (메뉴, 첫 화면, 읽은 것에서 만들 것으로, 첫 방문)
4. **4절 덜 된 화면** (PRD 세 탭, 휴대폰, 상태 화면, 계정 삭제, 도움말). 영어는 언어와 시장을 정한 뒤
5. **5절 새 기능 화면**은 해당 기능을 만들 때

각 단계가 끝나면 Hallmark 검사와 캡처(밝은 화면, 어두운 화면, 휴대폰)를 남깁니다.
