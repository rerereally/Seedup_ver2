# 사용자 확인 가이드

작성일 2026-11-18. [service-plan.md](service-plan.md) 9절 1단계 12번 "사용자 확인 시작"을 위한 문서입니다.
목표는 두 가지입니다. **어디서 막히는지**, 그리고 **무엇에 돈을 낼지**를 실제 사람에게 듣는 것입니다.

## 1. 누구를 모으나

| 묶음 | 인원 | 조건 | 어디서 찾나 |
|---|---|---|---|
| 바이브코더 | 6~10명 | Cursor, Claude Code, Lovable, Bolt, v0 중 하나로 최근 한 달 안에 뭔가 만들어 본 사람. 개발이 본업이 아니어도 됨 | 디스콰이엇, 오픈채팅 바이브코딩 방, 부트캠프 동기, X(트위터) |
| 사이드 프로젝트 개발자 | 4~6명 | 회사 일 외에 혼자 서비스를 만들거나 운영 중 | OKKY, GeekNews 댓글 작성자, GitHub에서 Seedup이 다룬 문제에 이슈를 단 한국인 |
| 출시해 본 사람 | 2~4명 | 실제 사용자가 있는 서비스를 혼자 또는 2~3명이 운영 | 디스콰이엇 메이커, 인디해커 모임 |

- 아는 사람만으로 채우지 않습니다. 절반 이상은 처음 보는 사람이어야 듣기 좋은 말만 듣지 않습니다.
- 한 번에 30~40분, 화면 공유(Zoom, Google Meet)로 합니다.
- 사례는 커피 쿠폰 정도면 충분합니다.

## 2. 진행 순서 (40분)

### 0~5분: 시작
- 이 서비스를 평가하는 자리가 아니라, 그 사람의 일하는 방식을 듣는 자리라고 말합니다.
- "솔직하게 별로라고 말해 주시는 게 가장 도움이 됩니다."
- 녹음해도 되는지 묻습니다.

### 5~15분: 지금 어떻게 하고 있나 (Seedup을 보여 주기 전)
제품을 보여 주기 전에 먼저 듣습니다. 보여 주고 나면 답이 제품에 끌려갑니다.

1. 최근에 만든 것(또는 만들려던 것)을 하나 이야기해 주세요. 무엇을 왜 만들었나요?
2. 그걸 만들기로 정하기 전에 무엇을 확인했나요? 어디서, 얼마나 시간을 썼나요?
3. 만드는 중에 가장 오래 막힌 곳은 어디였나요? 그때 어떻게 풀었나요?
4. 다 만든 뒤(배포, 첫 사용자, 보안, 비용)에 걱정했거나 실제로 사고가 난 게 있나요?
5. 개발 소식이나 새 도구는 어디서 보나요? 매일 보는 곳이 있나요? 왜 거기인가요?
6. 지금 돈을 내고 쓰는 개발 도구나 서비스가 있나요? 왜 그건 돈을 내나요? 끊은 것도 있나요? 왜 끊었나요?

### 15~30분: Seedup을 직접 써 보게 하기
설명하지 않고 맡깁니다. 막히는 곳에서 돕지 말고 "지금 무엇을 찾고 계세요?"만 묻습니다.

| 과제 | 볼 것 |
|---|---|
| A. 첫 화면에 들어와 이 서비스가 무엇인지 말해 보기 | 10초 안에 맞게 말하는가 |
| B. 관심 있는 글이나 저장소를 찾아 킵하기 | 읽을 글, 오픈소스, 맞춤 추천 중 어디로 가는가 |
| C. 만들고 싶은 아이디어 한 줄로 PRD 만들기 | 어디서 멈추는가, 원문 근거를 보는가 |
| D. 만든 PRD를 자기 코딩 도구에 넘기기 (MCP 연결 버튼) | 연결이 한 번에 되는가 |
| E. 오늘의 신호에서 만들 만한 문제 하나 고르기 | 원문을 믿는가, 무엇을 보고 고르는가 |

각 과제마다 적습니다.
- 끝까지 했는가(예, 도움 받고, 포기)
- 걸린 시간
- 처음 멈춘 곳과 그때 한 말

### 30~38분: 돈을 낼 기능 확인
아래 네 가지를 한 문장씩 보여 주고 각각 묻습니다. 화면이 없는 것은 말로만 설명합니다.

1. **만들 가치 검증 리포트:** 아이디어 하나에 실제 불만 원문, 경쟁 도구, 혼자 만들 때 규모, 첫 사용자 후보를 한 장으로.
2. **내 스택 레이더:** 내 저장소가 쓰는 라이브러리와 API에 생긴 일(서비스 종료, 큰 변경, 대안, 불만 급증)을 매일.
3. **PRD와 코드 대조 + 배포 전 점검:** 내 PRD 기준으로 다 만들었는지, 위험한 곳은 없는지, 고치기 프롬프트까지.
4. **지금 있는 것:** 큐레이션, 맞춤 추천, 주간 메일, PRD, MCP.

질문:
- 이 중 지금 가장 필요한 것 하나는? 왜?
- 그게 있으면 지난 한 달 중 언제 썼을까요? (구체적인 상황이 안 나오면 필요가 약한 것)
- 얼마면 내겠어요? 월 구독과 건당 중 어느 쪽이 맞나요?
- 이걸 대신하려고 지금 쓰는 것은? (없으면 문제가 작을 수 있음)

가격은 먼저 말하지 않습니다. 상대가 말한 뒤에 "월 1만 원이면요? 리포트 한 건에 5천 원이면요?"처럼 확인합니다.

### 38~40분: 마무리
- 오늘 본 것 중 다시 쓸 것 같은 게 있나요?
- 출시하면 알려 드려도 될까요? (연락처를 주는지가 관심의 신호)
- 비슷한 걸 겪는 사람을 한 명 소개해 줄 수 있나요?

## 3. 적는 법

한 사람마다 아래 표 한 줄을 채웁니다. 녹음은 다시 듣지 않아도 되게 그날 바로 정리합니다.

| 항목 | 예 |
|---|---|
| 묶음 | 바이브코더 |
| 최근 만든 것 | Cursor로 만든 가계부 앱 |
| 가장 오래 막힌 곳 | Supabase 인증 설정 |
| 출시 뒤 걱정 | API 키가 코드에 들어간 줄 몰랐음 |
| 매일 보는 곳 | GeekNews, X |
| 돈 내는 도구 | Cursor, ChatGPT |
| 과제 A~E 결과 | A 예, B 예, C 도움, D 포기, E 예 |
| 가장 필요한 기능 | 배포 전 점검 |
| 낼 의향과 방식 | 건당 5천 원 |
| 연락처 줌 | 예 |
| 기억에 남는 말 | "PRD는 ChatGPT로도 되는데, 근거 원문은 처음 봐요" |

## 4. 결과를 계획에 반영하는 기준

10명 이상 듣고 나서 판단합니다. 한두 명의 강한 의견으로 순서를 바꾸지 않습니다.

| 들은 것 | 계획에 반영 |
|---|---|
| 과제 하나에서 3명 이상 멈춤 | [ui-plan.md](ui-plan.md)에서 그 화면을 1순위로 |
| 한 기능을 "지난 한 달 중 이때 썼을 것"이라고 구체적으로 말한 사람이 30% 이상 | 그 기능을 2단계 맨 앞으로 |
| 한 기능에 돈을 내겠다는 사람이 없음 | 그 기능은 무료 기능으로 낮추거나 뺌 |
| 매일 보는 곳으로 Seedup 같은 큐레이션을 꼽은 사람이 적음 | 큐레이션을 입구로 둔 가정을 다시 봄 |
| 대신 쓰는 도구가 이미 충분하다는 답이 많음 | 그 영역은 차별점(검증된 원문) 없이는 하지 않음 |
