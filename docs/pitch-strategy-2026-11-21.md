## 1. 한 문장 승부 전략

> **"코드를 대신 짜는 또 하나의 AI가 아니라, Claude Code · Codex 바깥에서 '처음 정한 목표와 실제 원문 근거'를 고정하고 실제 코드로 판정하는 중심축"**으로 포지셔닝합니다.

해커톤에서 AI 도구 팀이 감점받는 흔한 패턴 4가지를 정면으로 뒤집습니다.

| 해커톤 흔한 감점 패턴 | Seedup의 역전 전략 |
| :--- | :--- |
| "그냥 ChatGPT / Claude 래퍼 아닌가?" | 에이전트를 대체하지 않고 **바깥**에서 목표 · 원문 · 교차 판정을 쥐는 구조를 명확히 대비 |
| "AI가 지어낸 그럴듯한 문장 아닌가?" | **모델을 믿지 않는 네 겹의 확인**(`isVerbatimQuote` → 2-Pass 군집 → `normalizeSpec` `H-n` 분리 → 교차 모델 P0 Critic)을 코드 원리로 설명 |
| "과장된 수치 · 빈 데모 · 미구현 포장" | `docs/scorecard.md` 실측값만 사용, 저장 PRD `0건`과 무료 모델 채점 한계를 **먼저 정직하게 공개**, 모든 기능에 `[운영 중]` / `[단계 1 구현 중]` / `[단계 2 계획]` 배지 분리 |
| "개발만 급해서 협업 · 문서화 점수(20점) 누락" | 2인(장차희 총괄·계획 / 정지훈 기술 구현·머지) + 멀티 에이전트 협업 체계를 **Seedup 원칙의 실증 사례**로 70초 배정 |

### 심사위원 기억에 남길 단 하나의 장면 (Signature Moment)
- `/prd/new` 화면에서 **① 원문 근거가 없는 요구사항이 서버 코드에 의해 자동으로 `H-n`(가설)로 분리되는 모습**, **② 근거 있는 요구사항을 눌렀을 때 실제 개발자 불만 원문(`E-n`)까지 추적 선이 켜지는 모습**, **③ 그 명세가 `AGENTS.md`와 `/agents` MCP로 코딩 에이전트에 바로 넘어가는 모습**을 하나의 끊김 없는 흐름으로 각인시킵니다.

## 2. 심사 기준표 5영역(100점) 득점 · 감점 방어 전략

### 01. 문제 정의 및 프로젝트 임팩트 (20점)
- **심사 질문:** 해결할 문제 명확성 · 실제 문제 해결 기여 · 적용 가능성과 기대효과
- **득점 전략 (0:00–1:30 + 시연):**
  - 코딩 에이전트 사용자가 실제로 겪는 3대 병목을 한 번에 짚습니다: ① 근거 없이 시작(아첨 · 환각), ② 세션 압축 · 도구 전환 시 목표 유실, ③ 만든 모델의 자가 보고 판정.
  - 대상을 "모든 개발자"가 아닌 **Claude Code · Codex를 쓰는 AI 네이티브 1인 빌더**로 좁혀 설득력을 높입니다.
  - 기대효과는 추상적 생산성 구호 대신 북극성 지표인 **목표 도달률(완료 시점 충족 성공 기준 비율)**로 못 박습니다.
- **감점 방어:**
  - "실제 사용 데이터가 있나?" → 운영 저장 PRD `0건` 기준선을 숨기지 않고 먼저 밝힌 뒤, 단계 0 무료 베타 공개 및 저장 흐름 점검으로 기준선 대비 변화를 추적하는 실행 계획을 제시합니다.

### 02. 아이디어의 독창성 및 혁신성 (20점)
- **심사 질문:** 기존과 차별화된 독창성 · 창의적 AI 활용과 새로운 가치 · 단순 구현을 넘은 관점
- **득점 전략 (1:30–2:40):**
  - **관점 전환:** "AI로 더 빨리 만들기"가 아니라 **"AI가 만든 결과를 AI가 믿지 않도록 바깥에서 제어하기"**라는 역발상을 전면에 둡니다.
  - `Claude Code · Codex vs Seedup` 5개 축 비교표(목표 / 기억 / 완료 판정 / 목표 이탈 / 무엇을 만들지)를 1장 슬라이드로 시각화해 차별점을 20초 안에 각인시킵니다.
- **감점 방어:**
  - 비교표의 우측(Seedup) 항목마다 `[운영 중]`과 `[단계 1~2 계획]`을 표기해, 계획 기능을 이미 다 만든 것처럼 보인다는 지적을 원천 차단합니다.

### 03. AI 기술 이해도 및 활용 적절성 (20점) — 핵심 변별력 구간
- **심사 질문:** 사용 기술과 원리 이해 · 문제 해결에 적합한 기술 선택 · 개선 가능성과 한계 고려
- **득점 전략 (5:20–7:30):**
  - **역할 분리 원리:** LLM은 초안 · 추출만 맡고, 채택(`isVerbatimQuote`) · 참조 무결성(`normalizeSpec`) · 정량 점수는 결정론적 코드가 맡습니다.
  - **적합한 기술 선택 근거 3가지:**
    1. 2-Pass 임베딩 군집(`clusterByEmbedding`)으로 입력 순서 의존 체이닝 방지.
    2. 작성 모델과 다른 모델의 교차 감사(`P0 Critic`)로 자기 칭찬 편향 완화.
    3. 무료 LLM의 실전 장애(생각 토큰 빈 응답 · 지연/멈춤 · 호출 실패)를 `16k` 출력 한도, `첫 토큰 15초 · 무응답 25초` 감시 후 모델 전환, 사용량 환불, `prd_cache` 캐시로 공학적으로 해결.
  - **정량 검증 증거:** `docs/scorecard.md` 고정 20건 실측 개선(`19/20 → 20/20`, 형식 지적 `0.7 → 0`, 내용 `3.0 → 7.4`, 시간 `64초 → 55초`, 검증 리포트 `200초 이상 → 49~94초`, 수집 8단계 `모두 성공 28분`, smoke `14/14`, 흐름 점검 `4/4`).
  - **한계 명시(3번째 하위 항목 정면 공략):** 무료 모델(`nvidia/nemotron-3-ultra-550b-a55b:free`) 1종 채점 한계, 근거 항목 최저(`2.8`), 인용 정밀도 `83% (52/63)` Claude 초안 판정(글자 대조 ≠ 관련성 보장), 저장 PRD `0건`을 솔직히 밝힙니다.
- **감점 방어:**
  - "100% 환각 방지", "10배 빨라졌다" 같은 미검증 · 과장 표현은 대본과 슬라이드에서 0건으로 유지합니다.
