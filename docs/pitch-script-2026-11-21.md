## 장면 1. 문제와 한 줄 정의 (0:00–0:50)

- **화면 경로:** 발표 슬라이드 (한 줄 정의 · 비교표) → `/` (홈 첫 화면)
- **상태 구분:** 문제 정의와 서비스 방향(`docs/supervisor-plan.md` 0절)

> Claude Code나 Codex로 혼자 제품을 만들다 보면, 코드보다 먼저 무너지는 것이 있습니다. **처음 정한 목표**입니다.
>
> 대화가 길어지거나 세션이 압축되면 처음 목표는 흐려집니다. 에이전트를 바꾸면 맥락은 도구마다 끊깁니다. 무엇보다 코드를 쓴 모델이 같은 세션에서 "다 했습니다"라고 스스로 보고하고, 근거 없는 요구사항도 요청받으면 그대로 만들어 버립니다.
>
> **Seedup은 처음 정한 목표를 중심축으로 고정하고, 기획부터 개발과 평가까지 흐름이 그 목표를 향하도록 잡아 주는 서비스입니다.**
>
> 대상은 Claude Code와 Codex를 쓰는 AI 네이티브 1인 빌더입니다. 코드는 기존 에이전트가 씁니다. Seedup은 그 바깥에서 세 가지를 쥡니다. **무엇을 왜 만드나**(목표 · 근거 · 명세), **어디까지 왔나**(진행 상태 · 다음 작업 · 사람 할 일), **정말 그렇게 됐나**(실제 코드 · CI · 화면으로 판정)입니다.
>
> 우리의 북극성 지표는 **목표 도달률**, 즉 완료 시점에 충족된 성공 기준의 비율입니다.

## 장면 2. 지금 되는 것 — 대표 흐름 시연 (0:50–2:20)

- **화면 경로:** `/` → `/newsletter-preview` → `/opportunities/[slug]` → `/prd/new` → `/spec/[id]` → `/agents` (필요 시 `/prd/validate`)
- **상태 구분:** 아래 장면은 **모두 지금 운영 코드에서 동작하는 기능**입니다.

> 먼저 **지금 바로 동작하는 대표 흐름**을 보여 드리겠습니다. 아이디어에서 원문, PRD, 그리고 `AGENTS.md`와 MCP 연결까지입니다.
>
> **[화면: `/` → `/prd/new`]**
> 지금 홈 화면(`/`)에서 아이디어 한 줄을 입력하면 `/prd/new`로 이어집니다. 공개 글에서 모아 둔 실제 개발자 불만 원문 중 가까운 글을 바로 찾아 보여 주고, 검증된 문제 목록을 둘러보려면 `/newsletter-preview`와 문제 상세 `/opportunities/[slug]`에서 원문과 기존 경쟁 도구를 확인할 수 있습니다. 이때 모델이 뽑은 인용은 **원문에 글자 그대로 있을 때만** 근거로 채택됩니다.
>
> **[화면: `/prd/new` (질문 → PRD 스트리밍 → 근거 추적 · 내보내기) → `/spec/[id]`]**
> 지금 `/prd/new`에서 아이디어에 맞춘 짧은 질문에 답하면 PRD가 실시간으로 생성됩니다. 생성이 끝나면 서버가 문서를 구조로 읽어 **증언(E) → 요구사항(R) → 기능(F) → 화면(S)** 연결을 강제합니다. 원문 근거가 없는 요구사항은 서버가 자동으로 **가설(H-n)**로 분리하고, 작성 모델과 다른 모델이 핵심 요구사항(P0)의 근거를 한 번 더 감사합니다. 완성된 PRD는 `/spec/[id]` 읽기 전용 링크로 공유할 수 있고, 아이디어의 반대 근거를 먼저 보는 검증 리포트도 `/prd/validate`에서 지금 동작합니다.
>
> **[화면: `/prd/new` 내보내기 → `/agents`]**
> 이렇게 만든 PRD는 `/prd/new`에서 `AGENTS.md`, `CLAUDE.md`, `.cursor/rules` 파일로 바로 내보낼 수 있습니다. 그리고 `/agents`에서 토큰을 발급해 Claude Code나 Codex 같은 에이전트에 Seedup MCP 서버를 연결할 수 있습니다. 지금도 에이전트가 MCP로 다음 작업을 받아 상태를 보고하고 커밋을 연결하며, 완료된 기능의 파일을 수정하면 자동으로 재확인 표시가 걸립니다.

## 장면 3. 앞으로 붙는 것 — 목표 잠금과 2단 검증 (2:20–3:20)

- **화면 경로:** 계획 화면 안내 — `/prd/new` (목표 잠금 카드 예정), `/agents` (로컬 훅 스타터 팩 예정), `/supervisor` (최소 대시보드 예정 — **현재 미구현**)
- **상태 구분:** 여기서부터는 **아직 구현되지 않은 단계 1~2 계획**입니다.

> 여기까지가 지금 되는 흐름입니다. 하지만 이 상태만으로는 두 가지가 비어 있습니다. PRD의 목표가 아직 에이전트 세션에 **강제 고정**되지 않고, 현재 `verify_feature`도 에이전트가 넘긴 diff를 검토하는 수준이라 **자가 보고 한계**가 남습니다.
>
> 그래서 **앞으로 두 단계의 핵심 고리**를 붙입니다.
>
> **첫째, 단계 1 계획인 '목표 잠금과 에이전트 연결'입니다.**
> 아직 미구현이며, 지금 PRD의 목표 · 하지 않을 것 · 성공 지표를 서버에 잠긴 목표(`G`)와 측정 가능한 성공 기준(`G-n`)으로 격상할 계획입니다. 목표는 `/prd/new`에서 확정하고, `AGENTS.md`와 MCP 응답, 그리고 세션 시작 · 압축 직전 로컬 훅으로 계속 다시 주입합니다. 결정 기록과 인수인계 메모도 서버 공유 메모리에 남겨, Claude Code에서 Codex로 도구를 바꿔도 같은 기억에서 이어 가게 할 계획입니다.
>
> **둘째, 단계 2 계획인 '2단 검증과 이탈 검사'입니다.**
> 역시 앞으로 만들 기능입니다. 1단은 커밋 전 로컬 훅이 시크릿 노출이나 빈 구현, 명세 이탈을 즉시 경고해 **로컬 확인**을 남깁니다. 2단은 push 뒤 Seedup 서버가 GitHub API로 실제 커밋 SHA와 CI 결과를 직접 읽어, 개발 모델과 다른 계열의 유료 모델로 완료 기준을 판정하고 코드 인용을 글자 대조해 **감독관 검증**을 확정합니다. 이 진행 상태와 이탈 경고는 단계 2에 추가할 `/supervisor` 대시보드에서 보여 줄 계획입니다.
>
> 정리하면 Claude Code · Codex와 다른 점은 분명합니다. 에이전트가 코드를 쓰는 **바깥**에서, 서버에 잠긴 목표 · 도구 중립 기억 · 다른 계열 모델의 실제 커밋 기반 판정 · 범위 이탈 경고를 쥐는 것입니다.

## 장면 4. 숫자 — 실측 성적표와 목표 채움 기준선 (3:20–4:20)

- **화면 경로:** 발표 슬라이드 (`docs/scorecard.md` 성적표 장 + 목표 채움 기준선 장)
- **상태 구분:** 아래 숫자는 모두 `docs/scorecard.md`와 `eval-results/2026-11-20-goal-baseline.json`에 기록된 **실측값**입니다.

> 지금 Seedup의 품질은 감이 아니라 **실측 성적표**로 관리하고 있습니다.
>
> 먼저 2026-11-19 기준, 고정 20건으로 반복 측정한 PRD 품질입니다.
> - 생성 성공은 **19/20에서 20/20**으로, PRD당 형식 지적은 **0.7에서 0**으로 줄었습니다.
> - 내용 종합 점수는 10점 만점에 **3.0에서 7.4**로 올랐습니다. 세부 항목은 구체성 **1.9 → 4.0**, 근거 **1.9 → 2.8**, 읽기 **3.2 → 4.65**, 실행 가능성 **1.6 → 4.2**, 완결성 **2.3 → 4.85**입니다. 다만 이 점수는 무료 모델(`nvidia/nemotron-3-ultra-550b-a55b:free`) 채점 기준입니다.
> - 생성 시간 중간값은 **64초에서 55초**로 줄었습니다.
>
> 운영과 신뢰 지표도 함께 재고 있습니다.
> - 운영 공개 인용 정밀도는 **83% (52/63)**이며, 현재 Claude 초안 판정 상태로 팀 확인이 진행 중입니다.
> - 검증 리포트 시간은 **200초 이상에서 49~94초**로 줄었고, 매일 수집 8단계는 Worker 시간 제한 실패에서 **모두 성공(아티클 생성 포함 28분)**으로 복구했습니다.
> - 운영 smoke는 **14/14**, 질문 → PRD → 수정 → MCP 흐름 점검은 **4/4** 통과했습니다.
> - 무료 모델 한계는 출력 한도 **16k**, 첫 토큰 **15초** · 무응답 **25초** 감시 후 모델 전환, 실패 시 사용량 환불, 캐시로 대응했습니다.
>
> 그리고 오늘(2026-11-20), 단계 1 목표 잠금에 앞서 운영 DB(`evidence_dossiers`)에서 지금 저장된 PRD들이 목표 · 하지 않을 것 · 성공 지표를 얼마나 채우고 있는지 읽기 전용 스크립트(`scripts/eval-goal.ts`)로 직접 기준선을 쟀습니다.
> 결과는 **저장된 운영 PRD 0건**, 따라서 세 섹션 채움 비율과 측정 가능한 성공 지표 비율 모두 **산출 불가(`— (0/0)`)**였습니다.

## 장면 5. 한계와 마무리 (4:20–5:00)

- **화면 경로:** 발표 슬라이드 (한계와 다음 계획) → `/`
- **상태 구분:** 현재 확인된 한계와 다음 단계 계획

> 마지막으로 한계를 숨기지 않고 말씀드리겠습니다.
>
> 1. **실사용 저장 데이터가 아직 0건입니다.** 오늘 잰 기준선처럼 운영에 저장된 개인 PRD가 **0건**이어서, 북극성 지표인 목표 도달률도 아직 측정 전입니다. 단계 0에서 저장 0건 원인을 확인하고 무료 베타로 실제 사용자를 만나야 합니다.
> 2. **근거와 채점 품질이 아직 완성되지 않았습니다.** PRD 내용 점수 **7.4/10**은 무료 모델 1종의 채점이고 그중 **근거가 2.8**로 가장 낮습니다. 인용 정밀도 **83% (52/63)** 역시 팀의 사람 라벨 확정이 남아 있습니다.
> 3. **목표 잠금과 2단 검증은 계획 단계입니다.** 발표에서 말씀드린 목표 잠금(단계 1), 2단 검증 · 이탈 검사 · `/supervisor` 대시보드(단계 2)는 이제 구현을 시작하는 단계이며, 화면 평가나 실측 토큰 트래커 등은 핵심 고리가 끝까지 돈 뒤로 미뤄 두었습니다.
> 4. **현재는 유료화보다 핵심 고리 검증이 먼저입니다.** 대표 흐름을 무료 베타로 검증하면서, 목표 잠금부터 감독관 검증까지 실제로 목표 도달률이 오르는지 같은 평가 스크립트로 증명하겠습니다.
>
> 코딩 에이전트가 더 빨라질수록, **처음 정한 목표를 바깥에서 붙잡고 실제 코드로 확인하는 축**이 더 중요해집니다. Seedup은 그 중심축을 만들겠습니다. 감사합니다.
