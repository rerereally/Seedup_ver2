## 2. UI 분석과 평가

점검 방법:
- 로컬 개발 서버를 앱 안 브라우저로 열어 봤습니다(데스크톱 1366px, 휴대폰 375px).
- 화면 9곳의 가로 넘침을 자동으로 검사했습니다.
- 영어 모드도 확인했습니다.
- DB 키가 없어서 뉴스·논문 같은 DB 화면은 빈 상태로 봤습니다.

### 점수 (10점 만점, 해커톤 심사 기준으로 본 주관 평가)

| 항목 | 점수 | 한 줄 평 |
|---|---|---|
| 첫인상·시연 효과 | 8.5 | 아이디어를 입력하면 증언 칩이 물리적으로 반응하는 홈 화면은 기억에 남습니다 |
| 시각 디자인 | 8 | 어두운 바탕, 절제된 색, 고정폭 숫자, 둥근 카드가 대부분 화면에서 일관됩니다 |
| 정보 구조 | 7 | 기회 상세의 흐름(상태 → 문제 → 빈틈 → 수치 → 근거)은 좋지만 너무 깁니다 |
| 핵심 기능 동선 | 6.5 | 가장 중요한 PRD 작업 화면이 오른쪽 좁은 칸(360px)에 갇혀 있습니다 |
| 모바일 | 7 | 가로 넘침은 없지만, 휴대폰에서는 PRD 버튼이 긴 스크롤 맨 아래에 있습니다 |
| 일관성 | 6.5 | 프로필·어드민이 아직 예전(V1) 스타일이고, PRD 카드만 밝은 색이라 튑니다 |
| 영어 대응 | 6 | 화면 문구는 대부분 영어로 바뀌지만, 기회 이름·문제 데이터는 아직 한국어입니다 |
| 접근성 | 7.5 | 칩·탭·버튼 의미, aria 표시, 모션 줄이기 설정 대응이 되어 있습니다 |

### 잘된 점
- **홈 화면의 직접 조작:** 증언 칩을 끌어서 폴더에 담으면 "근거 확인서"가 열립니다. 서비스가 하는 일을 설명 없이 보여주는 인터랙션입니다.
- **정직한 숫자 요약:** 증언 40 → 묶인 문제 28 → 기준 통과 2 → 열린 기회 1. 걸러지는 과정을 숨기지 않습니다.
- **기회 상세의 구성:** "왜 지금인가", "첫 10명 찾기", "만나면 물어볼 것"처럼 바로 실행할 수 있는 정보가 있습니다.
- **적중 기록:** 28개 중 13개(46%)에서 불만이 먼저 나왔고, 관련 도구는 중간값 52일 뒤에 나왔습니다. 숫자로 신뢰를 줍니다.

### 고쳐야 할 점 (영향 큰 순)
1. **PRD 작업 화면을 넓은 곳으로 옮기기.**
   - 지금은 근거 추적 네 칸(증언·요구사항·기능·화면)이 360px 칸에서 세로로 길게 쌓입니다.
   - 시연의 핵심 장면이므로 `/opportunities/[slug]/prd` 전용 화면이나 화면 전체 폭 섹션이 필요합니다.
2. **휴대폰에서 PRD 버튼이 묻힘.** 하단에 고정된 "PRD 만들기" 버튼이 필요합니다.
3. **홈 첫 화면의 빈 1~2초.** 칩이 떨어지기 전 화면이 비어 보입니다. 칩 문장이 잘려(…) 읽을 수 없는 문제도 있습니다. 칩에 마우스를 올리거나 포커스하면 전체 문장이 보여야 합니다.
4. **색 대비가 튐.** 어두운 사이트 안에서 PRD 카드만 밝은 색입니다. 의도라면 "문서"라는 은유를 더 살리고, 아니라면 어두운 색으로 맞춥니다.
5. **V1 잔재.** 프로필과 어드민 화면이 예전 스타일입니다.
6. **기회 상세가 너무 김.** 점수 내역·왜 지금·성장 기록을 접는 섹션이나 탭으로 묶으면 좋습니다.
7. **영어 데이터.** 엔진을 다시 돌려 `nameEn`·`problemEn`·`gapEn`을 채워야 합니다. 일부 화면의 탭 제목도 아직 한국어입니다.

## 4. 세계 해커톤 1등 전략

어떤 전략도 1등을 보장하지는 못합니다. 아래는 큰 대회 심사에서 반복해서 보이는 기준에 맞춘 것입니다. 그 기준은 새로움, 기술적 깊이, 완성도, 실제 효용, 발표입니다.

### 4.1 한 문장 포지셔닝
> **"Evidence-traced development: 실제 개발자의 불만에서 출발해, 모든 스펙 줄과 코드 작업이 검증된 원문으로 거슬러 올라가는 개발 파이프라인."**

- ChatPRD·Manyfast는 "기획서를 잘 쓰게" 도와줍니다. v0·Bolt는 "코드를 빨리 만들게" 도와줍니다.
- Seedup은 **"무엇을 만들지가 맞는지"를 증거로 보장**합니다. 그 증거를 코딩 에이전트까지 끊기지 않게 전달합니다.

### 4.2 심사위원이 기억할 3분 시연
1. **0:00 질문:** "AI가 코드를 1분 만에 짜는 시대에, 진짜 비싼 건 *쓸모없는 걸 만드는 것*입니다."
2. **0:20 홈:** "agent memory"를 입력합니다. 실제 HN·GitHub·Stack Overflow 원문 칩이 반응합니다. 칩을 폴더에 끌어 넣으면 근거 확인서가 "통과"로 바뀝니다.
3. **0:50 PRD:** "검증된 PRD 만들기"를 누릅니다. 화면 S-02를 누르면 그 화면을 정당화하는 증언 E-3이 강조됩니다. *"이 버튼 하나도 실제 사람의 말에서 나왔습니다."*
4. **1:30 개발 준비 슬롯:** 슬롯을 채우고 CLAUDE.md를 내보냅니다.
5. **1:50 MCP:** Claude Code 터미널에서 `search_opportunities`와 `generate_verified_prd`를 실행합니다. 에이전트가 F-01을 구현합니다. 미리 녹화한 영상을 함께 준비합니다.
6. **2:30 증명:** 적중 기록을 보여줍니다. "28개 중 13개에서 시장보다 먼저 문제를 짚었고, 중간값 52일 앞섰습니다."
7. **2:50 마무리:** "증거 없는 기획은 이제 그만."

### 4.3 더 추가하면 1등 가능성이 크게 오를 기능 (효과 대비 비용 순)
1. **스펙과 코드의 연결(Living Spec 검사)**
   - MCP·GitHub App이 PR을 볼 때, F별 "완료 기준" 슬롯과 실제 변경을 비교해 "F-02 완료 / 예외 처리 슬롯 미충족"을 PR 코멘트로 답니다.
   - 근거 → 스펙 → 코드 → 검증이 하나로 이어집니다. Manyfast와 가장 확실하게 갈리는 지점입니다.
2. **검증 지표 페이지(Seedup Benchmark)**
   - 인용 원문 일치율, 사람이 라벨링한 평가셋 기준 문제 묶음 정확도, 적중 기록의 정밀도를 공개합니다.
   - 세계 대회 심사위원은 측정 가능한 엄밀함에 높은 점수를 줍니다.
3. **증언 → 인터뷰 루프**
   - "첫 10명 찾기"에 연락 추적과 인터뷰 기록을 붙입니다.
   - 인터뷰 결과가 새 근거로 쌓여, 가설(H)이 요구사항(R)으로 바뀌는 순간을 시연할 수 있습니다.
4. **실시간 감시 알림:** 특정 기회를 "지켜보기"하면 새 증언이나 경쟁 도구 출시를 바로 알립니다. 지금의 다이제스트를 개인화한 형태입니다.
5. **다국어 수집원**
   - 영어권 Reddit·GitHub Discussions에 더해 한국(OKKY, 디스콰이엇)·일본(Qiita, Zenn) 개발자 커뮤니티를 수집합니다.
   - "같은 불만이 여러 나라에서 동시에 나온다"는 글로벌 신호는 다른 팀이 갖기 어렵습니다.
6. **데모 전용 안정성**
   - 대회 기간에만 유료 모델 예산을 조금 쓰고, 무료 모델은 실패 대비로 돌립니다.
   - 시연 동선의 모든 생성 결과를 리허설로 미리 저장해 둡니다.

### 4.4 대회 전 우선순위
1. **데이터:** 엔진을 다시 돌리고 인용을 검토해, 근거 기준을 통과한 기회를 10개 이상 만듭니다. 영어 필드도 함께 채웁니다.
2. **시연 화면:** PRD 작업 화면을 넓은 화면으로 옮기고, 3분 동선을 고정해 리허설합니다.
3. **MCP 실제 시연:** Claude Code 연결 영상을 녹화해 둡니다.
4. **4.3의 1번(스펙-코드 연결)** 최소 버전: PR 코멘트 하나만 동작해도 충분합니다.
5. **발표 자료:** 영어 발표본, 숫자 슬라이드(수집량·검증 통과율·적중 기록), 백업 영상.

### 4.5 예상 질문과 답
| 질문 | 답 |
|---|---|
| Manyfast·ChatPRD와 뭐가 다른가요? | 그 도구들은 입력한 아이디어를 잘 정리합니다. Seedup은 아이디어가 맞는지를 공개된 원문으로 검증하고, 그 근거를 코드 작업까지 추적합니다 |
| 28개 중 2개만 통과했는데 데이터가 빈약하지 않나요? | 기준을 일부러 엄격하게 잡았습니다(게시글 3건 이상, 플랫폼 2종 이상, 원문과 글자 단위 일치). 수집원을 늘리면 통과 개수는 늘어나고, 기준은 낮추지 않습니다 |
| 공개 글 인용은 문제없나요? | 원문 링크를 함께 걸고, 사람에게 자동으로 연락하지 않습니다. 삭제 요청이 오면 빼는 절차를 둡니다 |
| 무료 모델이 실패하면요? | 직전 결과로 대체하고, 사용 횟수는 돌려줍니다. 서버가 인용을 검증하므로 모델이 지어낸 근거는 통과하지 못합니다 |
