# Seedup 플랫폼 로드맵: 바이브코더·개발자를 위한 서비스로

작성일 2026-11-17. 해커톤 발표에서는 대표 기능만 보여 주고, 서비스는 바이브코더와 개발자가 매일 쓰는 플랫폼으로 키웁니다.

## 1. 한 줄 정의

**"뭘 만들지 찾고, 근거 있는 기획서로 정리하고, 코딩 에이전트로 만들고, 첫 사용자까지 찾는 곳."**

개발 단계별 메뉴 구조입니다. 해커톤에서는 "원문을 가리키는 PRD → 에이전트" 한 줄기만 시연합니다.

| 단계 | 화면 | 상태 |
|---|---|---|
| 발견 | 오늘의 신호(문제), 읽을 글, 오픈소스, AI 도구, 논문 | 있음 |
| 검증 | 기회 상세(원문·경쟁 도구·만들기 규모), 아이디어 평가, 원문 웹 검색 | 있음 |
| 기획 | PRD(문서 → 화면 설계 → 개발 준비 칸), 역기획 | 있음 |
| 만들기 | 에이전트 연결(MCP), AGENTS.md·CLAUDE.md·Cursor 규칙·빌더 프롬프트, 구현 체크리스트 | 있음 |
| 출시 | 첫 10명 찾기, 답글 초안 | 일부 |
| 성장 | 내 저장소 평가, 지켜보는 문제의 변화 알림 | 일부 |
| 내 공간 | 내 작업대(맞춤 추천), 보관함 | 있음 |

## 2. 근거 원문 분석 (2026-11-17, 운영 DB 기준)

| 지표 | 값 |
|---|---|
| 공개된 문제 | 29개 |
| 기준 통과(원문 3건·플랫폼 2곳) | 7개 (24%) |
| 원문 2건뿐인 문제 | 17개 (59%) |
| 원문 최대 | 5건 |
| 원문 출처 | HN 49건(66%), GitHub 16, Stack Overflow 5, 나머지 4곳 합쳐 4건 |
| 최근 실행 | 수집 1,471개 → 모델에 보낸 표본 360개(24%) → 고충 28개 → 후보 29개 |
| 모델 호출 실패 | 144번 중 18번 |

**원인**
1. 문제는 무작위 표본(360개)에서 발견되고, 발견된 뒤에는 그 문제만을 위한 검색을 하지 않았습니다. 그래서 대부분 원문 2건에서 멈춥니다.
2. 출처가 HN에 쏠려 있어 "플랫폼 2곳" 조건을 넘기 어렵습니다. 사용자 포럼 11곳을 붙였지만 원문은 1건뿐입니다.
3. 3주 동안 다시 발견되지 않으면 숨겨지므로, 원문이 쌓이기 전에 사라지는 문제가 있습니다.

**이번에 한 것**
- **원문 보충 검색**(`lib/opportunities/topup.ts`): 엔진이 돌 때마다 기준 미달 문제 12개(기준에 가까운 순)에 대해 그 문제만 검색하고, 엔진과 같은 엄격한 재검사("이 사람도 같은 문제를 겪는가")를 통과한 원문만 더합니다. 원문이 늘면 마지막 발견일도 갱신되어 숨겨지지 않습니다.
- 지금 결과에만 돌리는 명령: `npm run engine -- --topup-only --persist`

**다음에 할 것**
- 표본을 360개에서 600개로 늘리기(엔진 시간과 무료 모델 한도를 보고 조정)
- 수집처 다양화: Reddit(API 키 필요), GitHub Discussions 검색 비중 올리기, 한국 커뮤니티(OKKY, 디스콰이엇)
- 사용자가 직접 근거를 더하는 기능: 인터뷰 메모나 링크를 붙이면 서버가 원문을 받아 글자 대조 후 근거로 인정

## 3. 이번에 바꾼 것

| 영역 | 내용 |
|---|---|
| 내 작업대 | 아이디어 입력과 바로 가기, 처음 쓰는 사람에게 시작하기 체크리스트, 이어서 하기, 나를 위한 추천, 오늘 검증된 문제 |
| 추천 | 관심 분야·킵한 것·만드는 PRD를 임베딩해 문제·글·저장소·AI 제품을 섞어 추천하고 이유 표시. 이전에는 추천 엔진이 메일에만 쓰이고 화면에는 없었음 |
| PRD | 문서를 먼저 만들고 화면 설계는 버튼으로, 모델 선택은 작업 공간 상단에 항상 표시 |
| 메뉴 | 계정 버튼이 내 작업대로, 내 작업 메뉴에 작업대·저장소 평가 추가 |

## 4. 더 넣을 기능 (효과 대비 비용 순)

### 바로 할 것
1. **근거 직접 추가**: 링크를 붙이면 서버가 페이지를 받아 글자 대조 후 원문으로 인정합니다. 데이터 부족을 사용자가 메울 수 있습니다.
2. **PRD 버전 기록과 비교**: 대화형 수정마다 버전을 남기고 바뀐 줄을 보여 줍니다. 지금은 되돌리기가 한 단계뿐입니다.
3. **지켜보기 알림**: 지켜보는 문제에 새 원문이나 경쟁 도구가 생기면 메일로 알립니다(작업대에는 이미 "저장한 뒤 달라짐"이 있음).
4. **추천 피드백 반영**: 추천 옆 "관심 없음"을 받아 다음 추천에서 뺍니다(`recommendation_feedback` 테이블이 이미 있음).

### 다음
5. **스펙-코드 연결 검사**: GitHub PR의 변경을 기능별 완료 기준과 비교해 PR 코멘트를 답니다. MCP `mark_feature_done`과 이어집니다.
6. **기술 스택 추천과 시작 템플릿**: 만들기 규모 추정의 추천 스택으로 저장소 템플릿(Next.js+Supabase 등)을 바로 만듭니다.
7. **배포 전 점검표**: 바이브코딩 앱의 흔한 사고(비밀 키 노출, 인증 누락, RLS 꺼짐)를 저장소에서 찾아 알려 줍니다. Git 평가의 확장입니다.
8. **첫 사용자 추적**: 답글을 보낸 원문, 답이 온 사람, 인터뷰 메모를 기록하고, 메모가 가설(H)을 요구사항(R)으로 바꾸게 합니다.

### 나중
9. **공개 빌드 로그와 쇼케이스**: 이 PRD로 만든 결과물을 공개해 다른 사람이 보고 따라 만들 수 있게 합니다.
10. **팀 공동 작업**: PRD 공유 링크에 댓글과 편집 권한을 붙입니다.
11. **비용 계산기**: 모델·호스팅·API 비용을 기능별로 추정합니다.
12. **한국어 원문 수집**: OKKY, 디스콰이엇, 커리어리.

## 5. 확인하지 못한 것
- 바뀐 작업대와 PRD 화면은 로그인한 실제 화면으로 보지 못했습니다(로컬 로그인 불가). 배포 뒤 확인이 필요합니다.
- 원문 보충 검색은 로컬 사본에서만 실험했고 운영 DB에는 아직 쓰지 않았습니다.
