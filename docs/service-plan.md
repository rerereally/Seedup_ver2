# Seedup 서비스 분석과 작업 계획

작성일 2026-11-18. 실제 사이트(seedup.rerereally.com), 코드, GitHub Actions 실행 기록, 비슷한 서비스 조사를 직접 보고 정리했습니다.
기준은 하나입니다. **개발자와 바이브코더가 매일 쓰고, 돈을 내고서라도 쓸 서비스인가.**

화면과 사용 경험 작업은 [ui-plan.md](ui-plan.md)에 따로 적었습니다. 이 문서에서는 화면 작업을 해당 문서로 연결만 합니다.

이 문서는 다섯 가지를 답합니다.

1. 지금 무엇이 있고, 실제로 얼마나 잘 도는가 (2절, 3절)
2. 비슷한 서비스는 왜 돈을 받고, Seedup은 무엇이 다른가 (4절)
3. 무엇을 개선하는가: 이미 있는 기능의 속도, 안정성, 결과 품질 (5절)
4. 무엇을 추가하는가: 돈을 내고서라도 쓸 기능과 서비스 기본기 (6절, 7절)
5. 어떤 순서로, 무엇을 기준으로 끝났다고 보는가 (9절)

## 1. 한 줄 정의

**AI로 만드는 사람이 매일 보는 곳. 무엇을 만들지, 제대로 만들었는지, 내 스택에 무슨 일이 생겼는지.**

- 개발자 큐레이션(뉴스레터, 읽을 글, 오픈소스)이 매일 들어오는 이유이자 무료 입구입니다.
- 돈을 받는 쪽은 **검증된 원문을 근거로 한 깊은 결과물**(내 아이디어 검증 리포트, 내 스택 소식, PRD와 코드 대조)입니다.
- 이 모든 것이 하나로 이어집니다. 신호 → 검증된 원문 → PRD → 에이전트(MCP) → 만든 것 점검.

| AI 제품 | 개발과 먼 제품이 섞임 | 개발자용 큐레이션이라 부르기 어려움 |
| 프로젝트 | 빈 화면 노출 | 숨기거나 채워야 함 |

| 웹 원문 찾기 | 서명 키 환경 변수 이름이 달라 운영에서 503이었을 가능성 큼 | 고침(8절) |
| 영어 | 화면 26개 중 6개만 영어 지원 | 언어와 시장을 먼저 정해야 함(7절) |
| 사용량 | 조회수가 거의 0 | 무엇이 먹히는지 알 수 없음 |

## 3. 성능과 품질 진단 (실측)

구현은 대부분 되어 있지만, **얼마나 빠르고 안정적이며 결과가 좋은지는 지금까지 아무도 재지 않았습니다.** 아래는 직접 잰 값입니다.

### 3-1. 화면 속도

측정: 주요 화면 13개를 3번씩 요청해 첫 응답까지의 시간(TTFB)과 HTML 크기를 쟀습니다. 읽을 글은 브라우저에서 내려받는 파일도 셌습니다.

| 항목 | 실측 | 목표 |
|---|---|---|
| 첫 응답 시간 (모든 화면) | 0.58~1.42초. 로그인 화면도 0.6~0.9초. **정적 파일(favicon)도 0.85초** | 아래 참고 |
| 네트워크 (한국에서) | Cloudflare 연결이 홍콩(HKG)이나 로스앤젤레스(LAX)로 감. TCP 연결 0.15~0.22초, TLS까지 약 0.4초 | 서울 가까이 |
| 서버 처리 (TLS 이후) | 정적 파일 0.44초, 화면 0.38~0.43초. **화면과 정적 파일이 거의 같음** | |
| `/trends` HTML | 539KB (압축 62KB) | 100KB 이하 |
| 읽을 글 JavaScript | 19개 파일, 압축 전 약 491KB | 250KB 이하 |
| 글꼴 | 한 화면에 Pretendard 조각 17개, 약 440KB | 쓰는 굵기만 |
| 헤더 | 모든 화면에서 `/api/auth/is-admin`을 한 번 더 요청 | 0번 |

**다시 잰 결과, 느린 주원인은 서버가 아니라 네트워크 경로입니다.** 정적 파일과 화면의 첫 응답이 거의 같으므로, 서버에서 화면을 만드는 시간은 작습니다. 한국 사용자가 Cloudflare 무료 요금제로 접속하면 서울이 아닌 해외 거점으로 연결되는 경우가 많고, 이번 측정도 홍콩과 로스앤젤레스였습니다. 서울 거점(Cloudflare 상위 요금제나 서울 지역이 있는 다른 호스팅)으로 옮길지는 비용이 드는 결정이라 7절과 9절에 사용자 결정으로 넣었습니다.

그 밖에 코드에서 찾은 것(주로 로그인한 화면에 영향):

- **로그인 확인이 매번 네트워크 요청입니다.** `auth.getUser()`는 Supabase 인증 서버에 매번 물어봅니다. 35개 파일이 이 방식을 쓰고, 같은 요청 안에서도 여러 번 부릅니다.
- **목록 화면이 모든 열(`select('*')`)을 읽습니다.** 글 목록이 본문 전체까지 읽어서 HTML이 커집니다.
- **캐시가 거의 듣지 않습니다.** `lib/cache.ts`는 서버 메모리 캐시인데, Cloudflare Workers는 요청이 적으면 매번 새 인스턴스로 시작합니다.
- **로그인 안 한 사람의 화면도 매번 새로 만듭니다.** 하루 한 번 바뀌는 큐레이션 화면을 엣지에 저장해 두지 않습니다.

화면 쪽 무게 줄이기(JavaScript, 글꼴, 헤더, 로딩 화면)는 [ui-plan.md 3절](ui-plan.md#3-속도와-무게-화면-쪽)에 있습니다.

### 3-2. 데이터 수집 (매일 자동 작업)

측정: GitHub Actions 실행 기록 최근 8~9회.

| 작업 | 결과 | 걸린 시간 | 원인 |
|---|---|---|---|
| **큐레이션 수집** (`scheduled-ingest`, 매일 06시) | **최근 8번 중 7번 실패**, 11월 17일만 성공 | 35~57분 | GitHub 저장소 수집 단계가 시간 초과(응답 없음). 논문 단계 8~20분. 임베딩은 일부만 성공(207) |
| 기회 엔진 (`opportunity-engine`, 매일 07시) | 7번 중 6번 성공 | 14~29분 | 무료 모델 실패가 원인일 때가 있음 |

- 한 단계가 실패하면 작업 전체가 실패로 표시되고, 알림이 없어 아무도 모릅니다.
- 글 수집은 출처마다 5개(`rss?limit=5`)이고, 점수 기준(`minScore=50`)을 넘는 것만 남습니다.
- 무료 모델은 빈 응답이 잦습니다. 원문 보충 검색은 로컬 실험에서 원문을 0~1건밖에 늘리지 못했습니다.

### 3-3. AI 결과 품질과 안정성

| 기능 | 지금 알 수 있는 것 | 모르는 것 |
|---|---|---|
| 원문 인용 | 글자 단위 대조(`isVerbatimQuote`)와 서버 서명으로 지어낸 인용을 막음. **강점** | |
| 의미 검색, 임베딩 추천 | 운영에서 꺼져 있음. 수집 작업에는 `RAG_EMBEDDING_MODEL`이 있지만 운영 서버(Cloudflare Worker)에는 없는 것으로 보임 | |
| PRD 생성 | 성공 여부, 걸린 시간, 토큰, 비용이 `prd_runs`에 기록되고 관리자 화면(`/admin/ingest`)에 보임 | **성공률과 평균 시간을 아무도 확인하지 않음** |
| PRD 내용 품질 | 생성 뒤 자동 검사(근거 없는 요구사항, 숫자 없는 지표 등)가 있음 | 여러 아이디어로 돌려 보는 반복 평가가 없음 |
| 문제 발견 | 29개 중 22개가 기준 미달 | 사람이 보기에 쓸 만한 문제의 비율 |
| 추천 | 규칙과 점수는 있음 | 추천을 누른 비율, 킵 비율 |

### 3-4. 코드와 운영

- **오류 알림이 없습니다.** Cloudflare Workers 로그는 켜져 있지만(`wrangler.jsonc`의 `observability`), PRD 생성이나 MCP 호출이 실패해도 대시보드를 직접 열기 전에는 모릅니다.
- **로그인한 사용자 흐름의 자동 검사가 없습니다.** 단위 테스트는 117개지만, 로그인 → PRD → MCP 연결을 끝까지 도는 검사는 없습니다.
- **DB 변경을 사람이 직접 실행합니다.** SQL 파일(`prd_models`, `newsletter_issues`, `build_progress` 등)을 하나라도 빠뜨리면 운영에서 기능이 조용히 깨집니다.
- **MCP 사용량 제한**은 "읽고 나서 쓰기"라 동시에 들어온 요청 두 개가 한도를 넘을 수 있습니다. 코드에 알려 둔 한계이고, 사용량이 늘면 고칩니다.

## 4. 비슷한 서비스와 비교

가격은 대부분 제3자 비교 페이지 기준이라 공식 가격과 다를 수 있습니다.

| 영역 | 비슷한 서비스 | 돈을 받는 방식 | Seedup과 다른 점 |
|---|---|---|---|
| 개발자 큐레이션 | TLDR(구독 160만, 광고 한 번 최대 1만 8천 달러), daily.dev(기본 무료, Plus 월 약 15달러) | 독자는 무료, 광고주가 냄. 유료 구독은 부가 기능 | 독자 규모가 비교가 안 됨. 대신 내 저장소 기준 맞춤은 그쪽에 없음 |
| 문제와 아이디어 찾기 | IdeaBrowser(연 499~2,999달러), Exploding Topics(월 39~249달러), GummySearch(월 29~99달러, **Reddit API 약관 때문에 2026년 12월 1일 종료**) | 시간이 곧 돈인 창업자가 조사 시간을 삼. **내 아이디어 조사 리포트**와 커뮤니티에 돈을 냄 | Seedup은 원문을 글자 단위로 대조하고 서명함(그쪽은 "AI가 찾았다"). 출처가 개발자 사이트라 Reddit에 묶이지 않음. 대신 데이터 양(29개 대 1,000개 이상)과 내 아이디어 깊이 조사가 부족 |
| PRD와 기획 | ChatPRD(월 15달러, PM 10만 명 이상), 매니패스트(사용자 약 3만 명) | 기획이 직업인 PM이 업무 산출물로 삼. 업무 도구 연동과 팀 기능 | Seedup은 요구사항마다 실제 개발자 원문이 붙고 대상이 직접 만드는 사람. 업무 도구 연동과 팀 기능은 없음 |
| 에이전트 맥락 (MCP) | Context7(무료 + Pro 좌석당 월 10달러), Ref(크레딧) | 무료는 넉넉히, 비공개·팀·사용량에서 받음 | 그쪽은 라이브러리 문서, Seedup은 무엇을 왜 만드는지(PRD, 근거, 킵한 것). 겹치지 않음 |
| 바이브코딩 보안 점검 | Vibe App Scanner(월 29~49달러 또는 건당 5~19달러, MCP 지원), Lovable 내장(기본 무료, 침투 테스트 약 100달러), Supabase Security Advisor(무료) | 사고가 무서워서 냄. 건당 깊은 점검과 지속 점검 | Seedup에는 아직 없음. **경쟁이 많고 기본 점검은 무료로 풀려 있음** |

**사람들이 돈을 내는 공통 이유**

1. 시간이 돈인 사람의 조사 시간을 산다.
2. 직업 산출물을 빨리 만든다.
3. 무료로 써 보고, 비공개·팀·사용량에서 낸다.
4. 사고가 무서워서 낸다. 건당 결제가 잘 맞는다.
5. 사람과 커뮤니티에 낸다.
6. 독자는 안 내고 광고주가 낸다. 독자 규모가 먼저다.

**Seedup만의 것**

- 믿을 수 있는 근거: 글자 단위 대조와 서버 서명
- 개발자 출처(GitHub 이슈, HN, Stack Overflow). 한 플랫폼 약관에 묶이지 않음
- 신호 → 검증된 원문 → PRD → 에이전트가 한 줄로 이어짐. 다른 서비스는 한 칸씩만 함
- 한국어

**부족한 것**

- 데이터 양, 내 아이디어 깊이 조사, 독자 규모, 업무 도구 연동, 수집 안정성

**계획에 준 영향**

- '만들 가치 검증 리포트'를 추가 기능 맨 앞으로 올렸습니다. 돈을 받는 것이 증명된 분야이고 Seedup의 강점이 가장 잘 드러납니다.
- '배포 전 점검'은 단독 상품에서 'PRD와 코드 대조'와 묶은 기능으로 낮췄습니다.
- 데이터 양 목표를 1단계에 넣었습니다.
- **한 출처에 기대지 않는다**는 원칙을 넣었습니다. GummySearch의 교훈입니다.

## 5. 무엇을 개선하는가 (이미 있는 기능)

| 영역 | 개선 | 끝났다고 보는 기준 |
|---|---|---|
| 큐레이션 수집 | 단계별로 따로 실행하고 다시 시도, GitHub 단계는 나눠서 짧게, 실패하면 알림, 글 수집량 늘리기 | 2주 동안 매일 성공. 새 글이 하루 15편 이상 |
| 데이터 양 | 원문 보충 검색에 안정적인 모델 지정, 출처 늘리기(한국어 출처 OKKY, 디스콰이엇, GeekNews 검토). 한 출처가 전체의 절반을 넘지 않게 | 검증 통과 문제 7개 → 30개 이상, 매주 늘어남 |
| 큐레이션 품질 | '인기' 탭, AI 제품, 빈 화면 정리 ([ui-plan.md 1절](ui-plan.md#1-지금-바로-정리할-것)) | 첫 화면 10개 중 개발과 먼 주제 0개 |
| 뉴스레터 | 메일 키 설정 후 매주 발송, 내 관심사와 지켜보는 문제 반영 | 매주 월요일 발송, '지난 호'가 쌓임 |
| 오늘의 신호 | 실제 변화 속도에 맞게 주간 중심으로, 범위가 너무 좁은 문제 거르기 | 기준 통과 문제 중 사람이 보기에 쓸 만한 비율을 매주 확인 |
| 서버 속도 | 로그인 확인을 한 요청에 한 번만, 미들웨어는 `getClaims`, 헤더의 중복 인증 요청 제거, 트렌드 화면은 보여 주는 것만 전송 | 서버 처리 시간(TLS 이후)이 정적 파일과 같은 수준. 로그인한 화면에서 인증 요청이 요청당 1번 |
| 네트워크 경로 | 한국 사용자를 서울 가까운 거점으로(호스팅 또는 요금제 결정) | 한국에서 첫 응답 0.3초 이하 |
| 의미 검색과 추천 | 운영 서버에 `RAG_EMBEDDING_MODEL` 설정 | `/api/opportunities/match`가 결과를 돌려줌 |
| PRD 안정성 | `prd_runs`의 성공률과 시간을 확인하고 목표를 정함. 실패가 잦은 모델은 기본값에서 빼기 | 성공률 95% 이상, 절반이 40초 안에 끝남 |
| PRD 품질 | 아이디어 20개로 PRD를 만들어 자동 검사 점수를 비교하는 평가 세트 | 모델이나 프롬프트를 바꿀 때마다 점수가 떨어지지 않음 |
| 운영 | 오류 추적, 로그인 흐름 자동 검사, DB 변경을 자동 적용(마이그레이션), 쓰지 않는 코드 정리 | 실패가 생기면 하루 안에 알게 됨. 배포할 때 DB 변경이 빠지지 않음 |

## 6. 무엇을 추가하는가 (돈을 내고서라도 쓸 기능)

사람이 돈을 내는 순간은 **사고를 막을 때, 시간을 크게 아낄 때, 매일 일이 더 잘될 때**입니다(4절).
큐레이션과 뉴스레터는 무료 입구로 둡니다.

### 6-1. 만들 가치 검증 리포트 (시간을 크게 아낄 때, 가장 먼저)

- **누구:** 주말이나 몇 주를 쓰기 전에 확인하고 싶은 바이브코더, 혼자 만드는 개발자
- **무엇:** 아이디어 하나에 대해 한 장으로 줍니다.
  - 웹에서 찾은 실제 불만 원문(글자 대조와 서명)
  - 경쟁 도구
  - 혼자 만들 때의 규모
  - 첫 사용자 후보와 답글 초안
  - 결론: 만들 만한가
- **왜 돈을 내나:** IdeaBrowser 같은 곳이 이미 "내 아이디어 리포트"로 돈을 받습니다. Seedup은 근거를 믿을 수 있다는 점이 다릅니다. 웹 검색 비용이 들어서 건당으로 받기에 맞습니다.
- **지금 기반:** 웹 원문 찾기, 경쟁 도구 수집, 만들기 규모 추정, 첫 10명 찾기와 답글 초안.
- **만들 것:** 깊은 검색 단계(출처 여러 곳), 리포트 화면, 공유 링크용 공개 화면, 리포트 다음 단계로 PRD 바로 만들기.
- **품질 기준:** 리포트에 실린 원문은 100% 원문과 일치. 결론이 원문 수와 출처 수 기준(3건, 2곳 이상)과 맞아야 함.

### 6-2. 내 스택 레이더 (매일 일이 더 잘될 때)

- **누구:** 개발자, 바이브코더 모두
- **무엇:** 연결한 저장소의 라이브러리, API, AI 도구에 생긴 일만 골라 매일 보여 줍니다. 서비스 종료, 큰 변경, 보안 문제, 대안의 급부상, 그 도구에 대한 개발자 불만 급증.
- **실제 예:** 오늘의 신호의 'GIF 검색 API 대안'은 Tenor API가 공지 없이 종료된 데서 나왔습니다. 그 API를 쓰는 사람에게는 오늘 꼭 알아야 할 소식입니다.
- **왜 돈을 내나:** Dependabot과 Renovate는 무료로 보안 업데이트를 알리지만, "이 API를 쓰는 사람들이 지금 불만이 많다", "대안이 뜨고 있다"는 알려 주지 않습니다. 이번 조사에서 이걸 하는 서비스는 찾지 못했습니다. **다만 수요도 확인되지 않았으므로 사용자 확인(7절)으로 먼저 검증합니다.**
- **지금 기반:** 저장소 의존성 읽기, 매일 수집, 변경 알림 메일, MCP.
- **만들 것:** 의존성과 수집 데이터 연결, 내 스택 소식 화면, 메일과 MCP(`get_stack_news` 같은 도구)로 전달.
- **전제:** 수집이 매일 안정적으로 돌아야 합니다(5절).

### 6-3. PRD와 코드 대조 + 배포 전 점검 (매일 일이 더 잘될 때, 사고를 막을 때)

- **누구:** 개발자, 바이브코더
- **무엇:** 하나의 점검으로 묶습니다.
  - PRD의 기능별 완료 기준과 실제 저장소(또는 PR)를 비교해 빠진 것, 기준과 다른 것을 알려 줌
  - 흔한 사고(코드에 들어간 비밀 키, 브라우저로 새는 환경 변수, 꺼진 RLS, 인증 없는 API, 요청 횟수 제한 없음)를 찾음
  - 결과는 쉬운 말 설명과 **Cursor·Claude Code에 붙여 넣을 고치기 프롬프트**, MCP 도구
- **왜 묶나:** 보안 점검만으로는 Vibe App Scanner, Lovable과 Supabase의 무료 점검과 경쟁해야 합니다. "내 PRD 기준으로 다 만들었나 + 위험한 곳은 없나"를 한 번에 보는 것은 PRD가 있는 Seedup만 할 수 있습니다.
- **지금 기반:** MCP `get_build_checklist`, `mark_feature_done`, 기능별 진행 기록, '내 저장소 평가'(`lib/seeds/github.ts`)의 저장소 구조와 의존성 읽기.
- **만들 것:** 저장소 또는 PR 변경 읽기, 기준과 코드 비교, 점검 규칙, 결과 화면, 고치기 프롬프트, 비공개 저장소 접근(GitHub App).
- **품질 기준:** 일부러 문제를 심은 예시 저장소들에서 찾아야 할 것을 모두 찾고, 잘못된 경고가 적어야 합니다.

### 무료로 둘 것 (사람을 모으는 입구)

- 읽을 글, 오픈소스, AI 도구 큐레이션과 맞춤 추천
- 주간 신호 메일
- 오늘의 신호와 기회 상세
- PRD 하루 몇 개, 간단한 검증 리포트 맛보기
- MCP 기본 도구(킵한 것 가져오기, PRD 가져오기)

돈은 **깊이(리포트 건당), 비공개 저장소, 사용량**에서 받는 형태가 맞습니다(4절의 Context7, IdeaBrowser 방식).

## 7. 서비스 기본기와 빠진 영역

기능 외에, 사람들이 찾아오고 믿고 계속 쓰려면 필요한 것입니다.

| 영역 | 할 일 | 왜 |
|---|---|---|
| **실제 사용자 확인** | 바이브코더와 개발자 10~20명에게 직접 쓰게 하고 어디서 막히는지, 무엇에 돈을 낼지 듣기. 6절 기능은 만들기 전에 이 사람들에게 먼저 보여 주기 | 6절은 아직 가설. 조회수가 거의 0이라 측정만으로는 배울 게 없음 |
| **사람이 들어오는 길** | 검색으로 들어오는 공개 페이지(검증된 문제, 공개 PRD, 공개 리포트), 공유 링크, 뉴스레터 구독자 늘리기, 커뮤니티 활동 | 아무도 모르면 끝. 뉴스레터로 돈을 벌려면 독자 규모가 먼저(4절) |
| **첫 방문에서 쓸모 느끼기** | 가입에서 첫 맞춤 추천이나 첫 PRD까지 걸리는 시간과 비율 재기 ([ui-plan.md 2절](ui-plan.md#2-구조-들어와서-무엇을-할지-바로-알게)) | 가입 뒤 몇 분 안에 쓸 만하다고 느껴야 남음 |
| **언어와 시장 정하기** | 국내만 볼지, 해외도 볼지 결정. 그에 따라 원문 출처와 영어 화면 범위가 정해짐 | 지금 화면 26개 중 20개가 한국어 고정 |
| **Seedup 자체의 보안** | 저장소 권한 최소로 받기, 코드 저장하지 않기, 수집한 글 속 숨은 지시문(프롬프트 인젝션) 막기, 계정과 데이터 삭제 | 남의 코드를 읽는 서비스가 됨 |
| **결과의 안정성** | 돈을 받는 기능은 안정적인 모델 사용, 실패하면 사용량 돌려주기(이미 `releaseDailyUsage` 있음) | 무료 모델은 빈 응답과 실패가 잦음 |
| **호스팅 위치** | 한국 사용자가 서울 가까운 거점으로 연결되게. Cloudflare 상위 요금제, 서울 지역이 있는 호스팅 등을 비용과 함께 비교 | 지금은 홍콩과 로스앤젤레스로 연결되어 모든 화면이 0.8초 안팎(3-1) |
| **운영 비용** | 사용자 한 명이 한 달에 쓰는 모델, 웹 검색, 서버 비용 계산 | 무료로 어디까지 줄지 정하려면 필요 |
| **MCP 로그인 연결(OAuth)** | 토큰 없이 로그인만으로 Claude Desktop, claude.ai에서도 연결 | 버튼 한 번 연결의 완성형 |
| **측정** | 방문 → 킵 → PRD → 에이전트 연결 → 재방문, 리포트 이용 | 무엇이 먹히는지 보고 순서를 고치려면 필요 |
| **도움말과 피드백** | MCP 연결 안내, 자주 묻는 질문, 버그 신고 경로 ([ui-plan.md 4절](ui-plan.md#4-아직-덜-된-화면)) | 막혔을 때 갈 곳이 없음 |
| **한 출처에 기대지 않기** | 원문 출처를 여러 곳으로, 한 곳의 약관이나 API가 바뀌어도 서비스가 돌게 | GummySearch는 Reddit API 약관 하나로 종료 |
| **정책과 약관** | 원문 인용 정책(짧은 인용과 링크, 삭제 요청 창구), 이용약관, 개인정보처리방침("코드는 저장하지 않는다" 명시) | 공개 글을 인용하고 저장소를 읽는 서비스 |
| **디자인 일관성** | [ui-plan.md](ui-plan.md) 원칙과 검사 | 화면이 늘수록 다시 흐트러짐 |

## 9. 작업 계획

### 1단계: 바닥 다지기 (지금 있는 것이 빠르고 안정적으로, 사용자 확인 시작)

새 기능보다 먼저 합니다. 수집이 멈추고 화면이 느리면 무엇을 얹어도 비어 보이거나 떠납니다.

| 순서 | 할 일 | 누가 | 끝난 기준 |

## 10. 하지 않을 것

- 일반 AI 코딩 도우미: Cursor와 Claude Code가 더 잘합니다.
- 보안 점검만 따로 파는 상품: 이미 경쟁이 많고 기본 점검은 무료로 풀려 있습니다(6-3처럼 묶어서만).
- 팀 공동 작업: 개인 사용자가 먼저입니다.
- PRD 내보내기 형식 추가: 이미 충분합니다.
- Reddit처럼 한 플랫폼 약관에 기대는 수집.

## 11. 확인하지 못한 것

- 운영 DB는 직접 조회하지 못했습니다(로컬에 키가 없음). 기능 상태 수치는 공개 화면에서 읽었습니다.
- PRD 성공률과 걸린 시간, 사용자 수, 킵 수는 보지 못했습니다. 관리자 화면에서 확인해야 합니다.
- 화면 속도는 한 곳(한국)에서 3번씩 잰 값이고, 로그인 안 한 상태 기준입니다.
- 운영 서버의 환경 변수 목록은 볼 수 없어서, 임베딩이 꺼진 원인(`RAG_EMBEDDING_MODEL` 없음)은 코드와 응답으로 추정한 것입니다.
- 비슷한 서비스의 가격은 대부분 제3자 비교 페이지 기준입니다. 내 스택 레이더와 비슷한 서비스의 가격은 조사하지 않았습니다.
