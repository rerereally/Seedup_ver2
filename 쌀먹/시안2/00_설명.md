# 메인 기능 UI: 지금 사이트 기준

작성일 2026-11-16. 배포된 사이트(seedup.rerereally.com)의 홈, 기회 목록, 기회 상세, 스펙 작업 화면을 브라우저로 열어 스크린샷으로 본 뒤, 메인 기능 세 단계에 맞춰 다시 그린 화면입니다. 실제 앱 코드는 바꾸지 않았습니다.

## 여는 방법

`메인기능_UI.html`을 더블클릭합니다. 위쪽 단계 버튼이나 화면 안의 주황 버튼으로 세 단계를 오갑니다. `shared.js`가 같은 폴더에 있어야 합니다.

| 파일 | 내용 |
|---|---|
| `메인기능_UI.html` | 세 단계가 모두 들어 있는 화면 |
| `1_근거모으기.png` | 1단계 미리보기 |
| `2_스펙_만들기전.png`, `2_스펙_만든뒤.png` | 2단계의 두 상태 |
| `3_에이전트에넘기기.png` | 3단계 미리보기 |
| `모바일_스펙.png` | 좁은 화면(500px)의 2단계 |
| `../현재_사이트/` | 지금 사이트를 찍은 스크린샷 |

## 지금 사이트에서 본 것

| 화면 | 본 것 |
|---|---|
| 홈 | 첫 화면이 열리고 칩이 떨어지기 전까지 제목과 추천어만 보입니다. "입력해 보세요"라고 하지만 입력란이 눈에 보이지 않습니다. |
| 스펙 작업 화면 (`/prd`) | 만들기 전에는 밝은 카드 안에 버튼 두 개만 있습니다. 근거가 되는 원문조차 보이지 않습니다. 메인 기능의 첫 화면이 가장 비어 있습니다. |
| 메뉴 | 주 메뉴 4개와 더보기 5개입니다. 메인 기능과 무관한 항목이 절반을 넘습니다. |
| 기회 목록 | 숫자 네 개가 걸러지는 과정을 보여주는 띠가 잘 되어 있습니다. 그대로 살렸습니다. |
| 흐름 | 홈, 근거 확인서, 스펙 작업 화면이 따로 떨어져 있어, 지금 몇 번째 단계인지 알 수 없습니다. |

배포 사이트의 현재 숫자는 증언 89건, 묶인 문제 60개, 기준 통과 5개, 열린 기회 4개입니다. 이전 문서에서 저장소 스냅샷을 근거로 "기준 통과 2개"라고 쓴 것보다 늘어 있습니다.

## 그대로 가져온 것

- 색: 바탕 `#08080a`, 카드 `#131316`, 테두리 `#2a2a2f`, 주황 `#ff6a1f`, 초록 `#3ddc84`
- 알약 모양 메뉴, 흰색 로그인 버튼
- 굵고 자간이 좁은 제목(굵기 800~900)
- 모서리 20px 카드, 작은 회색 라벨
- 홈의 색색 증언 칩과 오른쪽 아래 폴더
- 기회 목록의 숫자 네 칸 띠

## 바꾼 것

**전체**
- 메뉴를 기회, 내 씨앗, 보관함 세 개로 줄였습니다.
- 메뉴 아래에 세 단계 표시를 넣었습니다: 근거 모으기, 스펙 만들기, 에이전트에 넘기기. 메인 기능이 무엇인지 어느 화면에서나 보입니다.

**1단계 근거 모으기**
- 입력란을 눈에 보이게 했습니다.
- 입력하면 관련 없는 칩은 흐려지고 관련 있는 칩만 남습니다.
- 폴더 안에 "이 근거로 스펙 만들기" 버튼을 넣었습니다. 지금은 폴더를 눌러 확인서를 연 뒤에야 버튼이 나옵니다.
- 기회 목록에 있던 숫자 띠를 홈 아래로 가져왔습니다.

**2단계 스펙 만들기**
- 만들기 전에도 원문 3건이 먼저 보입니다. 나머지 세 칸은 점선 자리 표시로 "여기에 무엇이 생기는지" 알려줍니다.
- "먼저 만들어 둔 예시 보기"를 넣었습니다. 로그인하지 않은 심사위원도 결과를 볼 수 있어야 합니다. 같은 근거의 직전 결과를 저장해 두는 기능이 이미 있으므로 그것을 보여주면 됩니다.
- 밝은 종이 카드 대신 사이트와 같은 어두운 보드를 썼습니다.
- 카드 사이를 선으로 잇고, 누르면 사슬이 주황색으로 켜집니다.
- 가설은 요구사항 칸에 섞지 않고 아래의 점선 구역으로 뺐습니다.
- 내보내기 버튼 다섯 개를 없애고 아래 고정 띠의 "에이전트에 넘기기" 하나로 모았습니다.

**3단계 에이전트에 넘기기**
- 지금은 프로필 화면과 스펙 화면 아래에 흩어져 있는 연결 명령, 파일 받기, 공유 링크를 한 화면에 모았습니다.
- 오른쪽에 에이전트가 실제로 받는 내용을 보여줍니다.

## 실제 앱에 옮길 때 손댈 곳

| 바꿀 것 | 위치 |
|---|---|
| 메뉴 줄이기 | `components/Header.tsx`의 `PRIMARY`, `MORE` |
| 단계 표시 | 새 컴포넌트 하나. 홈, `/prd`, 넘기기 화면에서 함께 씀 |
| 홈 입력란과 폴더 버튼 | `components/opportunity-stage/OpportunityStage.tsx`, `stage.module.css` |
| 만들기 전 원문 표시와 자리 표시 | `app/prd/page.tsx`가 이미 원문을 읽어 오므로 `PrdBuilder`에 넘겨 그리면 됨 |
| 연결선 | `PrdBuilder.tsx`의 근거 추적 보기. 사슬 계산은 `traceOf`가 이미 함 |
| 넘기기 화면 | `components/McpConnect.tsx`와 `PrdBuilder`의 내보내기 영역을 합침 |

## 확인한 것과 못 한 것

- 세 단계를 1440px에서, 2단계를 500px에서 렌더링해 겹침과 잘림을 확인하고 고쳤습니다.
- 지금 사이트의 스펙 화면은 만들기 전 상태만 봤습니다. 만든 뒤 상태는 로그인이 필요해서 화면이 아니라 `PrdBuilder.tsx` 코드로 확인했습니다.
- 홈의 물리 효과는 흉내 내지 않았습니다. 칩은 고정된 자리에 놓여 있습니다.
- 화면의 원문 3건과 칩 문장은 실제 데이터이고, 요구사항·기능·화면·가설 내용은 예시입니다.
- 1단계와 3단계의 좁은 화면은 확인하지 않았습니다.
