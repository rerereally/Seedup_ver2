# Seedup 전면 개편 계획 (소개 페이지 + 앱 전체)

작성일 2026-11-18. 매니패스트(manyfast.io/ko), Linear(linear.app), 토스 회사 소개(toss.im/company)를 앱 안 브라우저로 직접 열어 글과 화면 구성을 읽고 정리했습니다.
기존 [ui-plan.md](ui-plan.md)의 원칙(빈 화면 금지, 로그인 화면 직접 확인, Hallmark 검사)은 그대로 이어받고, **화면 구조와 디자인 시스템은 이 문서로 새로 잡습니다.** 이 문서가 확정되면 [DESIGN.md](../../DESIGN.md)를 먼저 고치고 코드에 들어갑니다.

## 1. 세 사이트에서 본 것

### 매니패스트 (가장 가까운 비교 대상)
- **어두운 첫 화면, 두 문장, 두 버튼.** "AI와 개발하는 팀을 위한 / 코드와 연결된 기획서" + 한 문장 설명 + `무료로 시작하기`(밝은 버튼) / `도입 문의하기`(어두운 버튼) + 아래 작은 안심 문구("카드 등록 없이 시작 · 문서 암호화 적용"), 그 아래 "2,000+ 팀" 신뢰 숫자.
- **제품이 하는 일을 움직이는 장면으로 보여 줌.** Figma, Notion, Slack, Jira 같은 도구에서 온 카드들이 흘러가다가, 그중 네 장이 가운데 기획서 창으로 모여 근거로 붙습니다. 설명 대신 장면.
- **번호 붙은 5단계 기능 소개(01~05).** 단계를 고르면 오른쪽에 실제 제품 화면(PRD, 기능명세서, 유저플로우, 와이어프레임, 공유)이 바뀝니다. 목업이 아니라 실제 UI를 축소해 넣은 수준.
- **기능 섹션마다 한 가지 이야기 + 실제 화면 + "○○ 보기" 링크.** 초안 만들기 → 내보내기 → 버전 기록 → 공동 편집 → 커넥터(Claude Code, Cursor MCP) → 코드와 연동되는 기획서(출시 예정). 각 링크는 기능 상세 페이지로 감.
- **후기 카드** (이름, 직함, 두 단락).
- 메뉴: 주요 기능, 리소스, 요금제, 가이드, 엔터프라이즈 / 로그인 / 무료로 시작하기. 소개 사이트와 앱이 분리되어 있음.

### Linear
- **아주 짧은 첫 문장 + 바로 아래 실제 앱 화면이 통째로.** "The product development system for teams and agents" 한 줄, 한 줄 설명, 그리고 사이드바·이슈 상세·활동 기록이 다 보이는 진짜 앱 화면이 히어로 그 자체입니다.
- **선언문 한 단락 + 원칙 세 개**(Purpose-built / Powered by agents / Designed for speed).
- **제품 영역을 큰 덩어리 4개로**(Intake, Planning, AI and automations, Build review ship). 덩어리마다 제목 두 줄, 한 단락, `Learn more →`, 실제 화면 장면, 그 아래 하위 기능 탭(`Linear Agent +`, `Triage +` …)을 펼치는 줄.
- 어두운 바탕, 거의 흑백, 얇은 테두리, 아주 옅은 그라데이션 빛. 강조색을 거의 안 씀.
- 앱 자체는 **왼쪽 사이드바**(Inbox, My issues, Workspace, Projects, Favorites) + 가운데 목록/상세 + 오른쪽 속성 패널. 키보드와 ⌘K 명령창 중심.

### 토스 회사 소개
- **밝은 바탕, 큰 영문 한 단어 + 한국어 한 줄**("Daily Greatness / 일상 가까이에서 변화를 만들어가는 토스"), 뒤에 옅은 파란 빛 번짐.
- **왼쪽 작은 라벨, 오른쪽 본문**의 두 칸 구성("● Vision" | 큰 문장 + 단락). 섹션이 Vision → History → Group → Culture → Leaders 순으로 같은 틀을 반복.
- History는 연도 탭(2025 / 2024-2021 …)으로 카드 목록 전환. Culture는 01~08 번호 + 영문 원칙명 + 한국어 한 줄 + 설명. Leaders는 이름과 한 문장 인용.
- 스크롤하면 흐림에서 또렷하게 나타나는 효과. 마지막에 큰 사이트맵 푸터.

*확인 한계:* 매니패스트와 Linear는 스크롤 애니메이션과 WebGL 장면이 앱 안 브라우저에서 빈 화면으로 찍혀, 일부 섹션은 페이지 글과 구조로만 읽었습니다.

## 2. 세 곳에서 가져올 것 (공통점)

| 공통점 | Seedup에 적용 |
|---|---|
| 첫 화면은 한 줄 제목, 한 문장, 버튼 두 개. 나머지는 **실제 제품 화면**이 말함 | 히어로 오른쪽(또는 아래)에 진짜 PRD 화면(근거 추적이 켜진 상태)을 넣음. 지금의 `SignalToSpec`을 실제 앱 화면 수준으로 키움 |
| 기능을 **번호 붙은 몇 덩어리**로 묶음 (매니패스트 01~05, Linear 4영역, 토스 01~08) | Seedup의 흐름 4단계: 01 신호 찾기 → 02 원문 검증 → 03 PRD → 04 에이전트로 만들기 |
| 섹션마다 **한 가지 이야기 + 실제 화면 + 상세 링크** | 각 단계가 기능 상세 페이지(`/product/...`)로 이어짐 |
| 소개 사이트와 앱이 **분리** | 로그인 전 `/`와 기능·소개 페이지는 마케팅 틀, 로그인 후는 사이드바 앱 틀 |
| 흑백 중심, 강조색은 아주 적게 | 초록(seed)은 "원문으로 확인됨"과 주요 버튼에만. 지금 규칙 유지 |
| 큰 제목은 짧고 굵게, 자간 좁게. 영문 단어를 디자인 요소로 | 섹션 라벨을 짧은 영문 한 단어로(Signal, Evidence, Spec, Agent) + 한국어 제목 |
| 등장 효과는 흐림·투명도·살짝 위로. 과하지 않음 | `opacity`/`transform`/`filter: blur`만, 240ms 안팎, 모션 줄이기 설정이면 없음 |

## 3. 새 구조

### 3-1. 소개 사이트 (로그인 전)

| 주소 | 무엇 | 참고 |
|---|---|---|
| `/` | 랜딩 (4절) | 매니패스트 + Linear |
| `/product/evidence` | 원문 검증: 글자 대조, 가설 분리, 적중 기록 | 매니패스트 기능 상세 |
| `/product/prd` | PRD: 근거 추적, 개발 준비 칸, 내보내기 | 〃 |
| `/product/agents` | 에이전트: MCP 도구, 연결 버튼, 진행 표시 | 〃 |
| `/about` | Seedup 소개 (5절) | 토스 회사 소개 |
| `/guide` | MCP 연결 안내, 자주 묻는 질문, 피드백 창구 | ui-plan 4절의 "도움말" |
| `/pricing` | **결정 필요.** 유료 기능이 정해지기 전이면 만들지 않음 | |

메뉴: 기능(하위 3개) / 소개 / 가이드 / 로그인 / **무료로 시작하기**.
`/opportunities/[slug]`, `/spec/[id]`, 공개 리포트는 로그인 없이 열리는 공개 페이지로 두되, 소개 사이트 틀(상단 메뉴)로 보여 검색과 공유의 입구가 되게 합니다.

### 3-2. 앱 (로그인 후)

Linear처럼 **왼쪽 사이드바 + 본문** 틀로 바꿉니다. 사이드바 묶음은 ui-plan 2절의 세 덩어리를 그대로 씁니다.

```
[Seedup]            ⌘K 검색
작업대               (지금 HomeDesk)
─ 발견
  신호               (지금 /newsletter-preview + /opportunities)
  읽을 글            (/news, /papers)
  탐색               (/trends, /github-trends, /ai-products, /projects 그대로)
─ 만들기
  PRD               (/prd, /prd/new)
  아이디어 평가        (/ideas 그대로)
  에이전트 연결        (/profile의 MCP 부분을 꺼냄)
─ 내 공간
  보관함             (/scrap)
  내 저장소          (/seeds)
───────────
설정 · 테마 · 언어 · 계정
```

- **⌘K 명령창**: 검색(`/search`), 페이지 이동, "새 PRD", "아이디어 검증"을 한 곳에서. `/search` 화면은 명령창 결과의 전체 보기로만 남김.
- 휴대폰: 사이드바는 왼쪽에서 열리는 서랍, 하단 바는 작업대·신호·PRD·보관함 4개.
- **합치거나 숨길 것** (결정 필요): `/ideas`(아이디어 평가)는 PRD 시작 흐름과 겹침 → `/prd/new` 안 "먼저 검증하기" 단계로 합치기 추천. `/projects`는 데이터가 없으면 메뉴에서 숨김. `/newsletter-preview/[period]`는 신호 안 "지난 호" 탭으로.

## 4. 랜딩 `/` 섹션 순서

| # | 섹션 | 내용 | 참고 |
|---|---|---|---|

| 8 | 주간 신호 메일 | 이번 호 미리보기 + 구독 | |

## 5. 소개 `/about`

토스 틀(왼쪽 라벨, 오른쪽 본문)을 그대로 씁니다.

| 라벨 | 내용 |
|---|---|
| (히어로) | 큰 영문 한 줄(예: "Build from evidence") + 한국어 한 줄 |
| Why | README의 "왜 만들었나": 코딩은 10배 빨라졌는데 무엇을 만들지는 그대로 |
| Principles | 01~05 번호 원칙. 예: Evidence over Opinion(원문 없는 줄은 가설), Verify, don't trust(모델은 쓰고 서버가 판정), No single source(한 플랫폼에 기대지 않음), Show the real thing(실제 숫자와 날짜), Hand it to the agent |
| How it works | 매일 도는 엔진을 한 줄 그림으로 (수집 → 대조 → 묶기 → 경쟁 확인 → 기준) |
| History | 연도 대신 월 단위 탭: 2026-07 시작 → 11월 기회 엔진, MCP, 검증 리포트… (git 기록 기준, 실제 날짜) |
| Team | 정지훈, 장차희와 한 문장씩 |
| Contact | 피드백, 원문 삭제 요청 창구 |

## 6. 디자인 시스템 v2 (DESIGN.md 개정안)

| 항목 | 지금 | 바꿀 것 |
|---|---|---|
| 기본 테마 | 밝은 화면 기본, 다크 지원 | 소개 사이트와 앱 모두 밝은/어두운 화면 둘 다, 시스템 설정을 따름. 두 테마가 같은 완성도(9절) |
| 색 | 회색 단계 + 초록 seed | 회색 단계를 Linear처럼 더 촘촘히(배경 3단, 테두리 2단, 글자 4단). 초록은 원문 확인과 주요 버튼만. 소개 사이트에만 옅은 빛 번짐(초록·파랑 10% 이하) |
| 글자 | Pretendard 400/600/700, 디스플레이 64px | 유지. 디스플레이 최대 72~80px, 자간 -0.045em. 섹션 라벨은 Geist Mono 13px 영문 한 단어 |
| 모서리 | 10 / 16 / 24 | 앱 8 / 12, 소개 사이트 화면 틀 16~20 |
| 테두리와 그림자 | 얇은 선 | 어두운 화면에서는 그림자 대신 1px 밝은 선 + 위쪽 아주 옅은 하이라이트(Linear) |
| 제품 화면 틀 | 없음 | 소개 페이지의 실제 화면은 모두 같은 `ProductFrame`(창 틀, 그림자, 살짝 기울임 없음)에 넣음 |
| 움직임 | transform/opacity 160~240ms | 스크롤 등장(흐림 8px → 0, 아래 12px → 0), 숫자 올라가기, 흐르는 카드. 전부 화면에 보일 때만 시작, 모션 줄이기면 정지, JS 없이도 내용 보임 |
| 앱 컴포넌트 | 페이지마다 따로 | 사이드바, 페이지 머리(제목 + 한 줄 + 오른쪽 행동), 목록 행, 속성 패널, 빈 상태, 로딩 뼈대, 명령창, 토스트를 공통 컴포넌트로 |

이전 레퍼런스(디자인 레퍼런스 2차의 TechDaily, DEV_LOG)와도 같은 방향입니다: 흑백, 모노 라벨, 코드·터미널 카드.

| 화면 | 할 일 |

| 앱 틀 | `WorkShell`을 사이드바 틀로. `Header`는 소개 사이트 전용으로 |

## 9. 정한 것 (2026-11-18)

1. **기능은 바꾸지 않습니다.** 화면과 디자인만 바꿉니다. 3-2의 "합치거나 숨길 것"은 하지 않습니다: `/ideas`는 그대로 '만들기' 묶음에 두고, `/projects`, 지난 호 화면도 그대로 둡니다. 요금제 페이지는 만들지 않습니다.
2. **밝은 화면과 어두운 화면 둘 다** 지원하고, 소개 사이트와 앱 모두 시스템 설정을 따릅니다(헤더 전환 버튼 유지). 6절의 "소개 사이트는 어두운 화면 기본"은 취소합니다.
3. **강조색은 초록(seed) 유지.**
4. **로컬 `redesign` 브랜치에서 끝까지 개발**하고, 완성될 때까지 push와 PR은 하지 않습니다.
5. 영문 라벨은 소개 사이트(랜딩, `/about`, `/product/*`)의 섹션 라벨에만 Geist Mono 영문 한 단어로 씁니다. 앱 화면에는 쓰지 않습니다.
6. **로그인 후 첫 화면(가운데)은 PRD 작업 공간**: 아이디어 입력창, 이어서 하기, 최근 킵한 것. 오른쪽에 만들 만한 문제와 이번 주 변화.
7. **틀은 왼쪽 사이드바 앱**(로그인 후). 화면 폭을 채워 쓸모없는 공백을 없앰.
8. **오늘의 신호는 목록 먼저**, 점 지도는 오른쪽 작은 요약이나 탭으로.
9. **로그인 안 한 사람은 소개 랜딩**을 보고, 히어로 입력창에 아이디어를 넣으면 로그인 없이 앱 화면(초안)으로 들어감.

## 11. 화면 배치안

앱 화면은 모두 같은 틀입니다: 왼쪽 사이드바(240px) | 가운데 작업 | 오른쪽 맥락 패널(320px, 필요한 화면만). 가운데는 위에 페이지 머리(제목 + 한 줄 + 오른쪽 행동 버튼), 그 아래 바로 작업. 첫 화면에 위쪽 빈 여백 없음.

│ 작업대       │                                    │  추천)        │

│ ─ 만들기     │                                    │              │

│ 에이전트 연결 │                                    │              │

- **새 라이브러리 없이** CSS 스크롤 타임라인과 작은 IntersectionObserver만 씀. 움직이는 부분만 클라이언트 컴포넌트로.

- 첫 화면에서 아이디어를 치면 1초 안에 맞는 원문이 보이고, 맞는 게 없으면 "아직 없음, 웹에서 더 찾기"로 작업 공간에 이어짐.

- 모션 줄이기, 자바스크립트 끄기에서 내용이 다 보임.
- 린트, 타입 검사, 테스트, 빌드 통과.

### 13-5. 순서

1. `/product/*` 삭제, 상단 막대와 푸터 정리
2. 히어로와 바로 써 보기, 흐르는 원문 칩
3. 숫자 올라가기
4. 기능 스크롤 이야기 (가장 큼)
5. 원칙 카드 빛, 적중 기록 막대
6. 전 화면 폭과 테마 점검

### 13-6. 정한 것 (2026-11-18)

- `/about`, `/guide`는 페이지를 두되 **푸터에서만** 연결. `/product/*`는 삭제.
- 상단 막대는 **로고, 로그인, 무료로 시작하기**만. 가운데 메뉴 없음.
- 움직임은 **차분하게**(Linear 수준): 섹션 등장, 숫자 올라가기, 원문 카드가 차례로 나타나는 정도. 13-2의 흐르는 원문 칩, 고정 창 전환, 타이핑, 마우스 따라가는 빛은 하지 않음. 기능 소개 01~04는 단계마다 글과 화면을 나란히 쌓음.
- 바로 써 보기는 **메인에서 즉시 반응**: 치는 동안 맞는 문제와 실제 원문 카드가 히어로 아래에 뜨고, 버튼으로 작업 공간에 이어짐.

바뀐 순서
1. `/product/*` 삭제, 상단 막대(로고, 로그인, 시작하기)와 푸터 정리
2. 히어로의 바로 써 보기(즉시 매칭 결과 카드)
3. 숫자 올라가기, 적중 기록 막대 자라기
4. 기능 01~04 정리(단계별 글과 실제 화면), 전 화면 폭과 테마 점검
