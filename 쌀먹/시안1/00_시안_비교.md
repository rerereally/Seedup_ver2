# 메인 기능 화면 시안 3종

작성일 2026-11-16. 대상은 Seedup의 메인 기능인 스펙 작업 화면(`/prd`)입니다. 실제 앱 코드는 바꾸지 않았고, 브라우저에서 바로 열리는 독립 화면으로 만들었습니다.

## 여는 방법

같은 폴더의 html 파일을 더블클릭하면 열립니다. 세 파일 모두 `shared.js`를 함께 읽으므로 폴더째로 옮겨야 합니다. 글꼴은 인터넷이 연결되어 있으면 Pretendard, 없으면 맑은 고딕으로 나옵니다.

| 파일 | 내용 |
|---|---|
| `시안1_추적보드.html` | 증언·요구사항·기능·화면을 네 칸에 놓고 선으로 잇는 보드 |
| `시안2_주석문서.html` | 종이 문서를 읽으면서 옆에 원문이 따라오는 화면 |
| `시안3_에이전트콘솔.html` | 스펙을 코딩 에이전트에 넘기는 과정을 보여주는 세 칸 화면 |
| `*.png` | 각 시안의 미리보기 |

## 공통으로 지킨 것

- 지금 서비스의 색을 그대로 썼습니다. 어두운 바탕, 주황 강조색 `#ff6a1f`, 초록 확인색 `#3ddc84`입니다.
- 제목 굵기를 600으로 낮췄습니다. `docs/next-tasks.md`의 타이포그래피 방침을 따랐습니다.
- 가설은 세 시안 모두 점선 테두리로 구분했습니다. "아직 확정되지 않음"을 색이 아니라 모양으로 알립니다.
- 주황색은 "지금 선택한 사슬"과 "다음에 할 행동"에만 씁니다.

## 예시 데이터

증언 3건은 저장소 스냅샷에 있는 실제 원문입니다("제공사별 모델 스키마 차이" 기회). 요구사항, 기능, 화면, 가설, 개발 준비 칸의 내용은 화면을 설명하려고 제가 쓴 예시입니다.

## 시안 비교

| | 시안 1 추적 보드 | 시안 2 주석 문서 | 시안 3 에이전트 콘솔 |
|---|---|---|---|
| 한 줄 | 사슬 전체를 한눈에 | 읽으면서 근거 확인 | 넘기는 순간을 보여줌 |
| 강조하는 것 | 원문에서 화면까지 이어지는 선 | 문장마다 붙은 원문 번호 | 에이전트가 추측하지 않고 질문함 |
| 맞는 청중 | 발표장의 심사위원 | 기획자, 문서를 읽는 사람 | 개발자, 세계 해커톤 |
| 3분 시연 | 가장 강함. 카드 하나를 누르면 설명이 끝남 | 보통. 읽어야 이해됨 | 강함. 터미널이 움직임 |
| 휴대폰 | 한 줄로 쌓임, 선은 숨김 | 원문이 위로 올라감 | 세 칸이 차례로 쌓임 |
| 구현 부담 | 중간. 선 그리기가 새로 필요 | 낮음. 지금의 문서 보기를 고치면 됨 | 중간. 터미널 재생은 연출 |
| 약점 | 항목이 많아지면 선이 엉킴 | 한눈에 구조가 안 보임 | 근거를 따라가는 장면이 약함 |

## 추천

**시안 1을 기본 화면으로 하고, 시안 3의 오른쪽 칸을 마지막 단계로 붙이는 조합**을 권합니다.

- 발표의 핵심 장면은 "누르면 원문이 켜지고, 근거 없는 것은 따로 떨어진다"입니다. 시안 1이 이 장면을 설명 없이 보여줍니다.
- 시안 3은 "문서로 끝나지 않는다"를 보여주는 데 가장 좋습니다. 세계 해커톤 영상의 후반부에 그대로 쓸 수 있습니다.
- 시안 2는 지금의 문서 보기 탭을 대체하는 용도로 남깁니다. 적은 작업으로 가장 큰 개선이 나옵니다.

시안 1에서 항목이 열 개를 넘으면 선이 엉키므로, 선택하지 않은 선은 지금처럼 흐리게 두고 한 칸에 보이는 카드 수를 제한해야 합니다.

## 시안 4 근거 장부 (기능에서만 출발)

파일은 `시안4_근거장부.html`입니다. 앞의 세 시안과 달리 지금 사이트의 색과 모양을 쓰지 않고, 이 기능이 답해야 하는 질문에서 화면을 정했습니다.

- **질문 1: 요구사항마다 어떤 원문이 받치고 있는가.** 가로줄이 요구사항, 세로줄이 원문인 표로 답합니다. 점이 하나도 없는 줄은 요구사항이 될 수 없어 가설로 내려갑니다. 설명 없이도 "근거 없는 줄"이 빈 줄로 보입니다.
- **질문 2: 기능마다 에이전트가 추측 없이 만들 수 있는가.** 기능과 여섯 가지 준비 항목의 표로 답합니다. 빈 칸은 "물어볼 것"으로 표시됩니다.
- **맨 위 숫자 다섯 개**가 결과를 요약합니다. 모델이 제안한 4개 중 2개만 근거가 있다는 숫자가 한눈에 보입니다.
- **오른쪽 칸**은 줄이나 원문 번호를 누르면 내용을 보여줍니다. 가설을 누르면 "원문 더 찾기"로 이어집니다.

밝은 종이 바탕에 초록(근거 있음)과 주황(근거 없음, 미정) 두 색만 씁니다.

| | 시안 4 근거 장부 |
|---|---|
| 강점 | 항목이 수십 개로 늘어도 엉키지 않음. 근거가 없는 곳이 빈 칸으로 드러남. 숫자로 요약됨 |
| 약점 | 첫인상이 업무용 도구처럼 건조함. 홈의 물리 칩과 분위기가 다름. 좁은 화면에서는 표를 옆으로 밀어야 함 |
| 맞는 청중 | 실제로 매일 쓰는 사람, 엄밀함을 보는 심사위원 |
| 구현 부담 | 낮음. 표와 상세 칸뿐이라 선 그리기가 필요 없음 |

시안 1과 비교하면 시안 1은 3분 발표에서 강하고, 시안 4는 실제 사용과 항목이 많은 스펙에서 강합니다. 둘을 같은 화면의 보기 방식 두 가지로 두는 것도 가능합니다. 지금 앱에 이미 보기 전환 탭이 있으므로 "근거 추적" 옆에 "장부"를 추가하는 식입니다.

## 실제 앱에 적용한다면

- 시안 2: 같은 컴포넌트의 문서 보기.
- 시안 3: `components/McpConnect.tsx`와 내보내기 영역.

- 세 화면을 1440px 너비에서 렌더링해 겹침과 넘침이 없는지 확인했습니다.
- 좁은 화면은 시안 1만 500px 너비에서 확인했습니다. 실제 휴대폰 너비(390px 안팎)와 시안 2, 3의 좁은 화면은 확인하지 않았습니다.
- 실제 사용자에게 보여주고 반응을 받지는 않았습니다. 추천은 제 판단입니다.
