# Seedup 전면 시안

작성일 2026-11-16. 배포 사이트(seedup.rerereally.com)의 화면 16개를 모두 열어 본 뒤, 색과 스타일은 유지하고 구조와 화면을 메인 기능에 맞춰 다시 그린 시안입니다. 화면끼리 링크로 이어져 있어 눌러 가며 볼 수 있습니다. 실제 앱 코드는 바꾸지 않았습니다.

## 여는 방법

`index.html`을 더블클릭해서 시작합니다. 메뉴와 버튼을 누르면 다른 화면으로 넘어갑니다. 폴더째로 옮겨야 합니다.

| 파일 | 화면 | 미리보기 |
|---|---|---|
| `index.html` | 홈 | `미리보기/1_홈.png` |
| `opportunities.html` | 기회 목록 | `2_기회목록.png` |
| `opportunity.html` | 기회 상세 | `3_기회상세.png` |
| `spec.html` | 스펙 만들기 | `4_스펙_만들기전.png`, `5_스펙_근거추적.png`, `6_스펙_장부.png` |
| `handoff.html` | 에이전트에 넘기기 | `7_넘기기.png` |

| `ui.css`, `ui.js`, `spec-data.js` | 공통 스타일과 예시 데이터 | |

좁은 화면은 `11_모바일_홈.png`, `12_모바일_스펙.png`, `13_모바일_기회상세.png`입니다.

`../현재_사이트/`에 화면별 스크린샷이 있습니다.

| 화면 | 본 것 |
|---|---|
| 홈 | 입력란이 눈에 보이지 않고, 칩이 떨어지기 전까지 비어 있음. 스펙으로 가려면 폴더를 눌러 확인서를 열어야 함 |
| 기회 목록 | 숫자 네 칸 띠와 표가 잘 되어 있음. 60개가 한 번에 나열되고 기준 통과 5개가 묻힘 |
| 기회 상세 | 점수, 왜 지금, 성장 기록, 증언, 첫 10명이 한 줄로 길게 이어짐. "만들 만한가"의 답을 찾으려면 끝까지 읽어야 함 |
| 스펙 작업 화면 | 만들기 전에는 버튼 두 개만 있음. 내보내기 버튼 다섯 개가 맨 아래에 나열됨 |
| 내 씨앗 | 입력란 하나만 있고 결과가 어떻게 나오는지 알 수 없음 |
| 보관함 | 비어 있을 때 안내 한 줄뿐 |
| 프로젝트 | "아직 정제된 프로젝트가 없습니다"만 나옴 |
| 아티클, 트렌드, 오픈소스, AI 제품 | 내용은 많지만 기회와 이어지지 않음. 메뉴 다섯 칸을 차지함 |
| 로그인 | 왼쪽 문구와 칩이 잘 되어 있음. 시안에서는 손대지 않음 |
| 프로필, 온보딩 | 로그인해야 열려서 보지 못함 |

## 구조를 바꾼 것

**메뉴를 9개에서 4개로 줄였습니다.**

| 지금 | 시안 |
|---|---|
| 기회, 내 씨앗, 아이디어 평가, 보관함 | 기회, 내 씨앗, 보관함 |
| 오늘 읽을 것, 트렌드, 오픈소스, AI 제품, 프로젝트 | 읽을거리 한 화면 (오른쪽 위의 작은 링크) |

- 아이디어 평가는 홈의 입력란이 같은 역할을 하므로 메뉴에서 뺐습니다.
- 프로젝트는 내용이 없어 뺐습니다.
- MCP 연결은 프로필에서 "에이전트에 넘기기" 화면으로 옮겼습니다. 쓰는 순간에 필요한 자리입니다.

**한 줄기 흐름을 만들었습니다.** 기회 상세, 스펙 만들기, 에이전트에 넘기기 세 화면 위에 "근거 확인 › 스펙 만들기 › 에이전트에 넘기기" 표시가 있습니다. 지금 어디에 있고 다음이 무엇인지 항상 보입니다.

## 화면별로 바꾼 것과 이유

**홈**
- 입력란을 보이게 하고 예시 단어 세 개를 붙였습니다. 처음 온 사람이 무엇을 해야 할지 바로 압니다.
- 입력하면 관련 없는 칩이 흐려집니다. 휴대폰에서는 아예 숨깁니다.
- 폴더 안에 "스펙 만들기" 버튼을 넣어 한 번에 넘어갑니다.
- 아래에 기준을 통과한 기회 세 개를 놓았습니다. 입력하지 않고 둘러보는 사람을 위한 길입니다.

**기회 목록**
- "기준 통과만"을 기본으로 켰습니다. 가장 믿을 만한 5개가 먼저 보입니다.
- 찾기, 상태 고르기를 한 줄에 모았습니다.

**기회 상세**
- 맨 위에 판단 세 칸을 두었습니다: 수요, 빈틈, 시점. "만들 만한가"에 먼저 답합니다.
- 긴 내용은 탭 네 개로 나눴습니다: 현장 증언, 이미 있는 도구, 점수 내역, 첫 10명 찾기.
- 오른쪽 카드는 스크롤해도 따라옵니다.

**스펙 만들기**
- 만들기 전에도 원문이 먼저 보이고, 나머지 칸은 점선 자리 표시입니다.
- "먼저 만들어 둔 예시 보기"로 로그인 없이 결과를 볼 수 있습니다.
- 카드를 선으로 잇고, 누르면 사슬이 주황색으로 켜집니다.
- 가설은 아래 점선 구역으로 뺐습니다.
- 기능 카드에 "준비 5/6 · 물어볼 것 있음"을 표시합니다.
- "장부" 보기를 추가했습니다. 요구사항과 원문을 표로 대조하고, 기능별 준비 상태를 표로 봅니다.
- 내보내기 버튼 다섯 개를 아래 고정 띠의 "에이전트에 넘기기" 하나로 모았습니다.

**에이전트에 넘기기**
- 연결 명령, 파일 받기, 링크 공유를 한 화면에 모으고 추천 방법 하나를 강조했습니다.
- 오른쪽에 에이전트가 실제로 받는 내용을 보여줍니다.

**내 씨앗**
- 입력란 아래에 결과 예시를 바로 보여줍니다.
- 저장소마다 왼쪽에 가장 가까운 기회, 오른쪽에 다음 기능 세 가지와 "이슈 열기"를 놓았습니다.

**보관함**
- 제목을 "이어서 할 일"로 바꿨습니다. 저장소가 아니라 돌아올 이유를 보여주는 화면입니다.
- 저장한 뒤 달라진 점(새 증언, 경쟁 도구)을 카드에 표시합니다. 이 계산은 `lib/opportunities/insight.ts`의 `dossierChanges`에 이미 있습니다.
- 비어 있을 때의 화면도 넣었습니다("비어 있을 때" 탭).

**읽을거리**
- 메뉴 다섯 개를 탭 네 개가 있는 한 화면으로 합쳤습니다.
- 각 항목 옆에 "이어지는 기회"를 붙였습니다. 읽을거리가 메인 기능으로 돌아오는 길이 됩니다.

## 디자인 원칙

- **주황색은 한 화면에 하나.** 지금 해야 할 다음 행동에만 씁니다.
- **빈 화면을 두지 않습니다.** 결과가 없을 때는 무엇이 생길지 자리 표시나 예시로 보여줍니다.
- **확정되지 않은 것은 점선으로.** 가설, 정해지지 않은 준비 항목, 이어지는 기회 없음이 모두 같은 모양입니다.
- **숫자를 숨기지 않습니다.** 걸러지는 과정과 준비 상태를 숫자로 보여줍니다.

## 실제 앱에 옮길 때 순서

1. 메뉴 줄이기와 흐름 표시 (`components/Header.tsx`, 새 컴포넌트 하나)
2. 스펙 화면: 만들기 전 원문 표시, 연결선, 가설 구역, 아래 고정 띠 (`components/opportunity-stage/PrdBuilder.tsx`, `app/prd/page.tsx`)
3. 에이전트에 넘기기 화면 (`components/McpConnect.tsx`와 내보내기 영역을 합침)
4. 기회 상세: 판단 세 칸과 탭 (`app/opportunities/[slug]/page.tsx`)
5. 홈: 입력란과 폴더 버튼 (`components/opportunity-stage/OpportunityStage.tsx`)
6. 보관함, 내 씨앗, 읽을거리

## 예시 데이터

- 기회 이름, 설명, 숫자, 증언 3건, 점수 내역, 칩 문장, 아티클·트렌드·오픈소스 제목은 배포 사이트에 보이는 실제 값입니다.
- 요구사항, 기능, 화면, 가설, 준비 항목, 내 씨앗의 기능 제안, 읽을거리의 "이어지는 기회" 연결은 화면을 설명하려고 쓴 예시입니다.

## 확인한 것과 못 한 것

- 여덟 화면을 1440px에서 렌더링해 겹침과 잘림을 확인하고 고쳤습니다.
- 좁은 화면은 홈, 스펙, 기회 상세를 500px에서 확인했습니다. 실제 휴대폰 너비(390px 안팎)는 확인하지 않았습니다.
- 프로필과 온보딩은 로그인이 필요해 보지 못했고, 시안에도 넣지 않았습니다.
- 홈의 물리 효과는 흉내 내지 않았습니다. 칩은 고정된 자리에 있습니다.
- 스펙 화면의 "구조 트리", "유저플로우", "문서" 탭은 모양만 있고 눌러도 바뀌지 않습니다.
- 실제 사용자에게 보여주고 반응을 받지는 않았습니다.
