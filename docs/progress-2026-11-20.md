## 바뀐 결정

- **유료 사용자보다 무료 사용자 확보가 먼저입니다.** 코드를 확인해 보니 결제나 유료 잠금은 어디에도 없습니다. Google 로그인만 하면 모든 기능이 무료입니다(PRD 하루 10개, 검증 리포트 하루 3개, 질문 답하기는 로그인 없이). 그래서 계획의 "첫 유료 사용자 10명"과 "가격 대기 신청"은 뒤로 미루고, **무료 사용자의 활성화와 재방문**을 먼저 잽니다.
  - 지표: 홈 입력 → PRD 생성 비율, 저장 비율, 주간 MCP 재사용률.
- **로그인 없이 PRD 만들기는 아직 열지 않았습니다.** 무료 모델의 하루 호출 한도를 악용으로 다 쓸 위험이 있고, 하루 한도를 IP 기준으로 셀 저장소(새 테이블이나 Supabase 익명 로그인 설정)가 필요합니다. 결정이 필요합니다.

## 작업별 내용

### 3-5 저장 0건 원인 (#87)
- 운영 `evidence_dossiers`가 0건입니다. 가장 큰 이유는 외부 사용자가 없다는 점입니다(PRD 생성 97건, 사용자 3명).
- 그와 별개로 버그가 하나 있었습니다. `PrdBuilder`의 저장 버튼이 `!ids.length`이면 꺼져서, 원문을 담지 않은 아이디어 PRD는 저장할 수 없었습니다. 서버는 PRD 본문만으로도 저장을 받습니다.
- **확인하지 못한 것:** 로그인이 필요해 브라우저에서 직접 저장해 보지는 못했습니다.

### 1-2 요구사항과 원문의 의미 확인 (#88)
- 이미 있던 `auditP0Evidence`(`prd-audit.ts`)를 운영 PRD 생성에서 기본으로 켰습니다. 사이트 PRD, MCP `generate_verified_prd`, 관리자 미리 생성이 모두 해당됩니다.
- 감사 모델은 `prdFreeModels()` 중 작성 모델이 아닌 첫 모델입니다.
- 결과 처리: 뒷받침하지 않는 P0는 가설(H-n)로, 범위를 넘은 P0는 줄이고 열린 질문으로 남깁니다.
- `eval-prd.ts`도 기본으로 감사합니다(`--no-audit-p0`로 끔).
- **남은 것:** 같은 20건으로 감사 전후 시간과 결과를 재야 합니다. PRD 생성 시간이 최대 35초 늘 수 있습니다. P1 이하 요구사항은 아직 감사하지 않습니다.

### 1-3 경쟁 판단 (#89, 일부)
- `coverRivals`(`spec.ts`): 모델이 비교하지 않은 직접 경쟁 도구를 "아직 비교하지 않았습니다"로 PRD에 붙입니다. 생성과 수정 모두에 적용했고, 테스트를 1개 추가했습니다.
- **남은 것:** 경쟁 도구 검색 자체가 비는 문제(공개 PRD 7개 중 4개가 0개)입니다. 조사 에이전트(검색 반복과 설명 비교)가 필요합니다. 수집이 끝나기 전에는 `actors.ts`와 `web.ts`를 고치지 않고, `report.ts` 쪽에서 기존 검색 함수를 불러 쓰는 방식으로 만들 계획입니다.
