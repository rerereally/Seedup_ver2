# 시안 4: 기능과 사용 흐름에서 다시 시작한 화면

작성일 2026-11-16. 시안 1~3은 지금 사이트의 색과 모양을 유지했습니다. 시안 4는 그것을 쓰지 않고, 지금 실제로 있는 기능과 사용자가 거치는 순서만 보고 새로 그렸습니다. 실제 앱 코드는 바꾸지 않았습니다.

## 여는 방법

`index.html`을 더블클릭합니다. 문제 카드나 "이어서" 버튼을 누르면 `work.html`(작업 화면)로 넘어갑니다. 폴더째로 옮겨야 합니다.

| 파일 | 화면 | 미리보기 |
|---|---|---|
| `index.html` | 시작 | `미리보기/1_시작.png` |
| `work.html` | 작업 | `2_작업_스펙만들기전.png`, `3_작업_요구사항선택.png`, `4_작업_가설선택.png` |
| | 좁은 화면 | `5_모바일_작업.png`, `6_모바일_시작.png` |

## 출발점

지금 사이트는 기능마다 메뉴와 페이지가 있습니다. 하지만 사용자가 하려는 일은 하나입니다. **막연한 생각에서 시작해, 에이전트가 맞는 것을 만들기 시작하는 데까지 가는 것**입니다. 그래서 페이지를 기능별로 나누지 않고 이 한 가지 일의 순서대로 놓았습니다.

|---|---|---|

| 찾기 | 검색 화면 | 위쪽 찾기 칸 하나 |

## 시작 화면

사용자가 들고 오는 것은 셋 중 하나입니다. 그래서 첫 화면이 셋 중 하나를 묻습니다.

- **아이디어가 있어요.** 적으면 같은 문제를 말한 글을 찾습니다. 지금의 홈 입력과 아이디어 평가를 합친 자리입니다.
- **아이디어가 없어요.** 기준을 통과한 문제 5개에서 고릅니다. 지금의 기회 목록입니다.
- **이미 만들고 있어요.** 저장소를 읽고 다음 기능을 찾습니다. 지금의 내 씨앗입니다.

그 아래는 순서대로 다음과 같습니다.

- **이어서 하기.** 하던 작업, 지금 단계, 다음에 할 일이 보입니다. 저장한 뒤 새 증언이 붙었으면 형광펜으로 알립니다.
- **확인된 문제.** 기준을 통과한 5개만 먼저 보이고, 나머지 55개는 링크 하나 뒤에 있습니다.
- **어떻게 걸러지나.** 숫자 네 개를 칸으로 나누지 않고 한 문단으로 읽게 했습니다.

## 작업 화면

세 칸입니다.

- **왼쪽: 단계.** 문제, 근거, 스펙, 준비, 넘기기. 단계마다 지금 상태가 한 줄로 붙습니다("말 3건 · 기준 통과", "2칸 남음"). 끝난 단계는 초록 표시가 됩니다.
- **가운데: 한 장의 문서.** 다섯 단계가 위에서 아래로 이어집니다. 다른 화면으로 넘어가지 않습니다.
- **오른쪽: 말한 사람들.** 항상 보입니다. 가운데에서 줄을 누르면 그 줄을 받치는 말만 남고 나머지는 흐려집니다.

단계별 내용은 다음과 같습니다.

| 단계 | 하는 일 | 지금 사이트에서 가져온 기능 |
|---|---|---|
| 1 문제 | 만들 만한지 세 칸으로 판단 (수요, 빈틈, 시점) | 기회 상세의 점수, 왜 지금, 경쟁 도구 |
| 2 근거 | 스펙에 쓸 말을 체크로 고름. 기준 통과 여부가 바로 바뀜 | 홈의 폴더와 근거 확인서 |
| 3 스펙 | 요구사항 아래 기능, 기능 아래 화면이 들여쓰기로 이어짐 | 스펙 작업 화면의 근거 추적, 대화로 고치기 |
| 4 준비 | 기능마다 정해지지 않은 것을 그 자리에서 정함 | 개발 준비 슬롯 |
| 5 넘기기 | 터미널 연결, 파일, 링크 | 내보내기, MCP 연결, 공유 링크 |

## 새로 정한 약속

**형광펜과 점선.** 이 시안의 장식은 이것 하나입니다.

- 받치는 말이 있는 문장에는 노란 형광펜이 칠해집니다.
- 아직 아무도 말하지 않은 문장에는 점선 밑줄이 그어집니다.
- 원문에서도 핵심 구절에 같은 형광펜이 칠해져 있어, 요구사항과 원문이 같은 표시로 이어집니다.

지금 사이트가 번호(E-1, R-01)와 색 테두리로 알려주는 것을 문장 자체의 모양으로 알려줍니다. 번호는 작게 남겨 두었습니다.

**사람의 말은 다른 글씨로.** 원문 인용은 명조 계열 글씨로 보여줍니다. 서비스가 쓴 문장과 사람이 쓴 문장이 눈으로 구분됩니다.

**낱말.** "증언", "기회", "가설" 대신 "사람들이 한 말", "문제", "아직 아무도 말하지 않은 것"이라고 썼습니다. 처음 온 사람이 설명 없이 읽을 수 있습니다.

## 사용 흐름에서 고친 것

| 지금 겪는 불편 | 시안 4 |
|---|---|
| 어디서 시작할지 모름 | 첫 화면이 세 가지 중 하나를 묻습니다 |
| 스펙 화면에 가면 근거가 보이지 않음 | 근거가 오른쪽에 항상 있습니다 |
| 근거를 바꾸려면 홈으로 돌아가야 함 | 같은 화면의 2단계에서 체크를 켜고 끕니다 |
| 네 칸을 가로로 오가며 읽어야 함 | 요구사항, 기능, 화면이 들여쓰기 한 줄기로 읽힙니다 |
| 빈 준비 칸은 에이전트가 묻기를 기다림 | 그 자리에서 답을 적어 정할 수 있고, 맡길 수도 있습니다 |
| 다음에 뭘 해야 할지 모름 | 왼쪽에 단계별 상태와 남은 일이 있습니다 |
| 저장한 뒤 달라진 것을 모름 | 시작 화면의 "이어서 하기"에 표시됩니다 |
| 가설을 어떻게 할지 모름 | 가설을 누르면 "같은 말 더 찾기"와 "물어볼 질문 보기"가 나옵니다 |

## 넣지 않은 것

- **읽을거리(아티클, 트렌드, 오픈소스, AI 제품).** 이 한 가지 일의 순서에 들어갈 자리가 없어 뺐습니다. 넣는다면 1단계의 "이미 있는 도구" 옆에 "배경 자료"로 접어 넣는 것이 맞습니다.
- **홈의 물리 칩.** 지금 사이트에서 가장 기억에 남는 장면입니다. 이 시안은 쓰기 편한 쪽을 택했고, 그만큼 첫인상의 재미는 줄었습니다.
- **뉴스레터, 추천, 관리자 화면.**

## 확인한 것과 못 한 것

- 두 화면을 1440px에서 렌더링해 겹침과 잘림을 확인했습니다. 진행 표시가 보이지 않던 것과 조사가 틀린 문구 하나를 고쳤습니다.
- 작업 화면을 500px에서 확인했습니다. 시작 화면의 좁은 화면은 수정 뒤 다시 보지 않았습니다.
- 좁은 화면에서는 "말한 사람들" 칸이 맨 아래로 내려갑니다. 줄을 눌렀을 때 바로 보이지 않으므로, 실제로 만들 때는 아래에서 올라오는 창으로 바꿔야 합니다.
- 위쪽 찾기 칸은 눌렀을 때 예시 목록만 나오고 실제로 찾지는 않습니다.
- 실제 사용자에게 보여주고 반응을 받지는 않았습니다. "사용 흐름에 맞췄다"는 것은 지금 사이트의 화면과 코드에서 읽어낸 흐름을 기준으로 한 제 판단입니다.
