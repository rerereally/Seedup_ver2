## 2. 코드 작업 (우선순위 순)

### A. Manyfast 느낌 UI 적용 (사용자 결정 대기)
"추천안대로 적용" 또는 "일부만 고르기" 답을 받은 뒤 진행합니다. 물리 효과 홈과 주황 강조색은 유지합니다. 차별점("바깥 시장에서 검증된 개발자 원문 + 경쟁 확인 + 적중 기록")이 화면에 드러나야 합니다.
1. **홈 스크롤 스토리텔링:** 물리 효과 아래에 흩어진 불만 → 같은 문제로 묶임 → 원문 검증 → PRD 한 줄이 원문 E-n을 가리키는 장면을 넣습니다.
2. **제품 창 목업:** `/prd` 작업 화면을 창 버튼 세 개가 달린 앱 창 틀로 감쌉니다.
3. **타이포그래피:** 큰 제목 굵기를 800~900에서 500~600으로 낮추고 여백을 늘립니다.
4. **카드 톤 통일:** 밝은 PRD 카드를 어두운 반투명 카드로 바꾸고, 메뉴는 스크롤하면 작아지게 합니다.

### B. UI 평가에서 남은 것
- **홈 첫 화면:** 칩이 떨어지기 전의 빈 1~2초를 줄입니다. 칩에 마우스를 올리거나 포커스하면 잘린 문장 전체가 보이게 합니다.
- **기회 상세:** 점수 내역·왜 지금·성장 기록을 접는 섹션이나 탭으로 묶습니다.
- **V2 디자인:** 프로필과 어드민 화면을 V2 디자인으로 바꿉니다.
- **영어 번역:** 씨앗, 보관함, 아이디어 평가, 로그인 화면을 번역합니다. 화면별 탭 제목(예: "기회 | Seedup")도 넣습니다.

### C. 세계 대회용 기능 (`final-report.md` 4.3)
1. **스펙과 코드 연결(Living Spec 검사):** PR의 변경을 F별 "완료 기준" 슬롯과 비교해 PR 코멘트를 답니다. 코멘트 하나만 동작하는 최소 버전부터 만듭니다.
2. **검증 지표 페이지:** 인용 원문 일치율, 문제 묶음 정확도, 적중 기록 정밀도를 보여줍니다.

## 4. 작업 규칙
- **빌드 후 정리:** 빌드하면 `next-env.d.ts`가 바뀝니다. 커밋 전에 `git checkout -- next-env.d.ts`를 실행합니다.
- **글자 색:** 이 다크 테마에서 `text-white`는 어두운 색으로 바뀝니다. 밝은 배경 위 글자는 `text-[#111113]`, 어두운 배경 위 글자는 `text-[#fbfbfa]`처럼 색을 직접 씁니다.
- **번역:** 새 문구는 `translator(lang)`의 `t('한국어', 'English')`로 씁니다. 서버에서는 `getLang()`, 클라이언트에서는 `LangProvider`로 언어를 받습니다.
- **비밀 값:** 실제 키는 `.env.example`에 넣지 않습니다. 비밀 값은 사용자가 직접 넣습니다.
- **커밋과 합치기:** 커밋과 push는 사용자가 요청할 때만 합니다. main 합치기는 사용자가 합니다.
- **병렬 작업:** 서로 독립된 작업은 Haiku 5.5 서브에이전트에 worktree로 나눠 맡기고, 결과 브랜치를 검토한 뒤 합칩니다.
- **시연 데이터:** 무료 모델은 자주 실패합니다. 시연 전에 검토한 스냅샷을 고정해 둡니다.
